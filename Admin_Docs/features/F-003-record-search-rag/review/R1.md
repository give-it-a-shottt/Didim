## 지적
- [신규] [제안] [확실] `NoteMarkdown` 본문(note-markdown.tsx:155-208 근처)에서 `asMarkdown` 분기가 5번 반복된다(wrapper 클래스, `segments` 계산, `body`, 일반 조각 태그 `div`/`span`, 강조 상자 `Box`와 클래스). 동작은 맞고 시험이 두 모드를 모두 덮지만, 세 번째 모드(예: 일부만 마크다운)가 생기거나 강조 규칙을 바꾸면 5곳을 함께 고쳐야 한다. 또 `data-render-mode`가 이미 모드를 나타내는데 같은 판단이 여러 번 흩어져 있다 — frontend/src/components/note-markdown.tsx (compute `asMarkdown`부터 `segments.map` 끝까지) — diff 전체 기준으로 확인, 실제 파일은 함수 목록만 grep — 지금은 두어도 무방. 손댄다면 조각 하나를 그리는 작은 컴포넌트(`SegmentView({ segment, asMarkdown, highlighted })`)로 빼서 모드별 태그·클래스를 한 곳에서 정하고, `NoteMarkdown`은 나누기 + map만 남긴다.

- 3차 제안 2(드래그 로직이 SelectStep에 인라인) → 사용자 판정(W)으로 그대로 둠, 다시 지적하지 않음. 상태 관리 지도 66행의 `isDragging` · `dragDepth` 설명은 현재 구조와 일치.

## 체크 항목별 근거
- 프론트 구조(컴포넌트 책임) → note-markdown.tsx는 "원문 → 조각 묶음 → 그리기" 한 책임. 위치 변환(`toUtf16Offsets`, 15~29행대), 나누기(`splitByChunks`), 울타리 합치기(`mergeOpenFences`)가 각각 작은 순수 함수로 분리되고 파일 머리 주석이 "왜"(조각 단위로 가두기, 울타리가 경계에 걸림)를 설명. page.tsx는 `sliceByCodePoints` 호출과 mark 렌더를 걷어내 `<NoteMarkdown>` 한 줄이 되어 더 얇아짐. 지적은 위 [제안] 1건.
- 프론트 폴더 · architecture.md 일치 → components/note-markdown 설명 일치, 삭제된 lib/text-range 언급 없음. 일치.
- 프론트 상태 위치 → NoteMarkdown은 상태 없는 서버 컴포넌트, 새 전역/로컬 상태 없음. 상태 관리 지도에 추가할 항목 없음.
- 백엔드 구조 → `strip_markdown`은 search/query.py의 순수 함수, `make_excerpt` 첫 줄에서 호출. 라우터에 로직 없음, 의존 방향 변화 없음. `_MD_LINK` 길이 제한 이유가 주석에 있음(3차 S).
- 데이터 → 이번 변경에 모델 · 마이그레이션 없음. 해당 없음.
- 가독성(이름) → `toUtf16Offsets`, `splitByChunks`, `mergeOpenFences`, `hasOpenFence`, `Segment`, `NoteChunkRange`, `MAX_MERGED_SEGMENT_CHARS` 모두 역할이 보임. `NoteChunkRange`는 records.ts의 `NoteChunk`의 부분집합(구조적으로 호환)이라 중복 정의이지만, 컴포넌트가 필요한 값만 받게 한 것으로 허용.
- 가독성(길이) → 함수 모두 25줄 이하, 예외는 위 [제안]의 `NoteMarkdown`(약 35줄).
- 가독성(중복) → COMPONENTS의 h4 · h5 · h6 같은 클래스 3회는 3차에서 이미 허용 판단, 변동 없음. 다른 중복 없음.
- 가독성(매직 넘버) → 200_000 · 8_000은 이름 붙은 상수 + 이유 주석(스택 넘침 약 1만 자). 테스트의 `45000` · `1500` · 0.5초는 시험 값이라 허용.
- 가독성(죽은 코드) → `sliceByCodePoints`/text-range.ts 삭제 완료. `mark` 사용처는 시험에서도 `data-chunk-highlight`로 교체됨. 미사용 import 없음(tsc · eslint 통과는 패킷 신뢰).
- 가독성(주석이 "왜") → "이미지는 불러오지 않고 링크로", "서버가 오래 멈추지 않게", "겹치는 조각은 건너뜀(정상 데이터에서는 없음)", "원문 끝" 등 의도 중심. 시험 주석(3차 리뷰 S, T 판정)이 근거를 가리켜 추적 가능.

- 미확인 → 실제 렌더 결과 · react-markdown 동작 · 패킷의 시험 통과(메인 실행 결과 신뢰), 5.3초 렌더 한계는 문서화된 것으로 구조 지적에서 제외. D-017 본문과 package-lock은 보지 않음(R2/문서 영역).
