# Git 브랜치 전략

## merge와 rebase
merge는 두 브랜치의 기록을 그대로 두고 합친 지점에 merge 커밋을 하나 만든다. rebase는 내 브랜치의 커밋들을 대상 브랜치 끝으로 옮겨 다시 쌓기 때문에 기록이 한 줄로 깔끔해지지만, 옮겨진 커밋들은 해시가 바뀐 새 커밋이 된다.

## 공유 브랜치에서 rebase 금지
이미 원격에 올려 다른 사람이 받아 간 브랜치를 rebase하면 커밋 해시가 바뀌어서, 다른 사람의 기록과 어긋난다. 그래서 rebase는 아직 혼자 쓰는 작업 브랜치에서만 하고, main처럼 여럿이 쓰는 브랜치에서는 하지 않는다.

## force-with-lease
rebase한 브랜치를 원격에 다시 올리려면 강제 푸시가 필요하다. 이때 `--force` 대신 `--force-with-lease`를 쓰면, 내가 마지막으로 받아 온 뒤에 다른 사람이 원격에 새 커밋을 올렸을 경우 푸시를 거절해서 남의 커밋을 덮어쓰는 사고를 막는다.

## squash merge
PR을 squash merge하면 작업 브랜치의 커밋 여러 개가 main에는 커밋 하나로 들어간다. main 기록이 기능 단위로 정리되는 장점이 있지만, 작업 브랜치에서 남긴 중간 커밋 메시지는 main에서 따로 보이지 않는다.

## 되돌리기
이미 푸시한 커밋을 되돌릴 때는 `git reset`으로 기록을 지우지 않고 `git revert`를 쓴다. revert는 그 커밋의 변경을 거꾸로 적용한 새 커밋을 만들기 때문에, 다른 사람이 받아 간 기록을 바꾸지 않고 안전하게 되돌릴 수 있다.
