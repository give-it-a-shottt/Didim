## 지적 묶음 (메인)
- A. [위험] Content-Length 없는(chunked) 요청은 크기 상한 없이 끝까지, 그것도 로그인 확인 전에 받는다(FastAPI가 폼 본문을 인증보다 먼저 읽음). 비로그인 요청 하나로 메모리 약 1GB · 임시 디스크 무제한 — R2-1. 같은 뿌리: 머리말이 있어도 비로그인이 21MB를 보낸 뒤 401 — R2-6 [제안]. `app/api/upload_limit.py`, `app/api/notes.py`
- B. [위험] 제목 정규식이 공백이 긴 제목 줄에서 제곱 시간(ReDoS). 1MB 한 줄이면 약 1.5시간, 그동안 서버 전체 멈춤 — R2-2. 메인 재현: 공백 4,000개 0.09초 → 8,000개 0.36초. `app/importers/markdown.py:21`
- C. [위험] 제목 경로(heading_path)에 길이 상한이 없어 입력보다 수천 배 커짐 → 메모리 바닥 — R2-3. 메인 재현: 입력 3.6만 자 → 제목 경로 합계 4,002만 자. `app/services/chunking.py`
- D. [주의] `ChunkLocationError`를 잡지 않아 나누기 버그가 나면 요청 전체 500, 앞에서 저장한 파일 결과도 사용자에게 안 감(완료 기준 4) — R3-1, R1-7.
- E. [주의] DB 저장 실패 로그에 노트 원문 · 제목 일부가 남음(SQLAlchemy 오류 메시지에 INSERT 값 포함, 엔진에 hide_parameters 없음) — R2-4. 결정 5 "로그에는 user_id만"과 다름.
- F. [주의] [추정] 노트당 조각 수 상한이 없음. 1MB 파일 하나가 조각 13만 개, 20개면 요청 하나에 약 260만 행 — R2-5. DB 저장 시간은 미측정. ❓ 상한 값은 사용자 결정.
- G. [주의] 화면: 200인데 본문이 JSON이 아니면 예외가 나서 '처리 중'에 멈추고 모달을 닫을 수 없음 — R3-2. `src/lib/import-records.ts`
- H. [주의] 테스트: 저장 실패 → 그 파일만 실패 · 앞 파일 유지 경로와 중복 경쟁 경로를 지나는 테스트 없음 — R3-3. [제안] 나누기 경계 사례(닫히지 않은 코드 블록, 4칸 들여쓰기, 제목 단계 건너뜀, 정확히 1,500자) — R3-5. [제안] Playwright가 401 · 네트워크 실패 · 400/413 · 중복 섞인 결과를 안 봄 — R3-7.
- I. [주의] 라우터가 어댑터(`clean_filename`)를 직접 import — 레이어 규칙 위반 — R1-1.
