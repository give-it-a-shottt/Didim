# 선착순 쿠폰 이벤트 회고

## 쿠폰이 중복 발급되던 문제
팀 프로젝트 쇼핑몰에서 100장 한정 선착순 쿠폰 이벤트를 준비했다. 부하 테스트로 동시 요청 500개를 보내자 쿠폰이 117장 발급됐다. 남은 수량을 읽고 줄이는 사이에 다른 요청이 끼어들어 같은 수량을 읽고 있었다.

Spring 서비스에서 쿠폰 수량을 줄이는 부분을 Redisson 분산 락으로 감싸고, 락을 얻지 못한 요청은 0.5초까지만 기다린 뒤 "잠시 후 다시 시도해 주세요" 응답을 주게 했다. 같은 사용자가 두 번 받지 못하게 (쿠폰 ID, 사용자 ID)에 유니크 제약도 걸었다.

같은 부하 테스트를 다시 돌리자 정확히 100장만 발급됐고, 한 사용자에게 두 번 발급된 경우는 0건이었다.

## 낙관적 락과 비관적 락 정리
낙관적 락은 버전 번호를 두고 저장할 때 충돌을 확인한다. 비관적 락은 읽을 때부터 행을 잠가 다른 요청이 기다리게 한다. 충돌이 잦으면 비관적 락이, 드물면 낙관적 락이 유리하다고 한다.
