# F-008 근거 달린 자소서 초안 + 근거 검사

## 한눈에 보기 (코드 몰라도 OK)
상태: [주의] 설계 의도 받음(2026-11-13) — 구현 전.
언제: 6주차
무엇을: 문장마다 근거 칩, 근거 없는 문장 경고, 쓰기 → 검사 → 고치기 루프, 제출 시 확인창, 내가 고친 비율
왜: 공고와 맞는 내 카드를 문항에 맞는 문장으로 옮기되, 지어낸 문장은 근거 검사로 잡아내려고요.

## 설계 의도 (사용자 확인 — 코드 작성 전에 채움, 문장 정리사 사용)
- 이 기능이 해결하는 문제: 공고 분석으로 내 카드가 공고에 맞는 것은 확인했지만, 그걸 문항에 맞는 문장으로 옮기기 어렵다. 문항마다 매칭된 내 카드만으로 초안을 쓰고, 문장마다 근거를 붙여 근거 없는 문장을 바로 찾게 한다. (사용자 확인, 2026-11-13)
- 완료 기준(무엇이 되면 끝인지): (사용자 확인, 2026-11-13)
  1. 공고의 문항마다 [초안 쓰기]를 누르면, 그 공고에 매칭된 내 카드만 AI에 보내 글자 수 제한 안의 초안을 만든다. 보내는 범위는 화면에 안내한다.
  2. 문장마다 근거 칩(카드 · 칸)이 붙고, 근거 인용이 그 카드 칸에 글자 그대로 있는지 서버가 검사한다. 검사를 못 넘은 문장은 '근거 없음'으로 경고한다.
  3. 초안을 직접 고쳐 저장할 수 있고, 근거 없는 문장이 남은 채로 상태를 '제출'로 바꾸면 '근거 없는 문장 N개' 확인창이 뜬다.
  4. 평가: 가상 공고 · 카드로 '지어낸 문장을 검사가 잡은 비율'과 '근거 없이 남은 문장 수'를 재서 남긴다.
- 정한 것 (사용자 선택, 2026-11-13): 근거 없는 문장은 경고만 하고 고치기는 내가 한다. AI는 문항당 1번 부르고, AI 자동 고치기는 2차 후보로 둔다(D-003에 반영).
- 정한 것 (사용자 선택, 2026-11-13): ① 고치기는 문장 단위(고치기 · 지우기 · 사이에 새 문장) — 고친 문장은 근거 칩을 유지하고 '내가 고침' 표시, 새 문장은 근거 없음. ② AI 초안이 글자 수 제한을 넘으면 저장하고 경고만('1,120 / 1,000자'), 줄이기는 내가. ③ 초안이 있는 문항에서 다시 쓰면 확인창 뒤 덮어쓰기(문항당 초안 하나, AI가 실패하면 이전 초안 유지). ④ 자소서 탭에서 문항 추가 · 수정 · 삭제(초안 있는 문항을 지우면 초안도 같이, 확인창).
- 화면 · 컴포넌트 (사용자 확인, 2026-11-13): 지원 상세 [자소서] 탭(APL_02_003, 사이드바 접힘). 문항 목록 · 문항 편집, 문장마다 근거 칩 · '근거 없음' · '내가 고침', 글자 수, 오른쪽에 고른 문장의 근거(카드 칸 인용 — 명조). 머리에서 상태를 '제출'로 바꿀 때 근거 없는 문장이 있으면 확인창. 모양은 Figma 원본(D-019).
- API (사용자 확인, 2026-11-13): `GET /api/applications/{id}/drafts`(문항별 초안 · 문장 · 근거, 쓸 수 있는 카드 수) · `POST /api/applications/{id}/questions/{qid}/draft`(AI 초안 — 그 공고에 매칭된 카드만, 매칭 카드 0장이면 409 · 카드 만들기 안내 — D-003 예외 7) · `PUT /api/drafts/{id}`(문장 단위로 고친 것 저장) · `PUT /api/applications/{id}/questions`(문항 목록 저장) · 지원 상세 응답에 `unsupported_sentence_count`. AI 답은 문장마다 {문장, 카드 번호, 칸, 근거 인용} — 보낸 카드 안인지 · 인용이 그 칸에 글자 그대로인지 서버 검사(F-007 매칭과 같은 방식), 못 넘은 문장은 근거 없이 남김.
- 데이터 (사용자 확인, 2026-11-13): 버전 파일 0008 — `drafts`(문항당 하나, AI 원문 — '내가 고친 비율'용), `draft_sentences`(순서 · 글 · 근거(카드 · 칸 · 인용 · 위치, 없으면 비움) · 출처 ai/user/edited), `draft_logs`(평가 로그). 선점은 F-007 공고 선점(`application_claims`)을 그대로 씀 — 같은 공고에서 분석과 초안 쓰기가 동시에 돌지 않음(D-020). 모두 user_id 조건(D-004).
