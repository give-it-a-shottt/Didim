## 지적
- [주의] [확실] `StructuredReply.attempts` 주석이 "실제로 AI를 부른 횟수(사용량 상한을 셀 때 씀)"인데, 이 값은 형식 검사 시도 횟수일 뿐이다. 연결 재시도(네트워크·5xx·타임아웃)는 OpenAICompatibleClient.chat 안에서 따로 최대 2번 요청하므로 실제 HTTP 호출 수는 attempts보다 많을 수 있다. 이 주석을 믿고 첫 AI 기능에서 하루 호출 상한(원칙 4)을 attempts로 세면 비용이 과소 집계된다 — 위치: backend/app/llm/structured.py:34 (연결 재시도는 backend/app/llm/openai_compat.py:104-110) — 확인한 범위: structured.py 전체, openai_compat.py chat 루프, LLMReply에 호출 횟수 필드 없음 확인 — 고치는 방법: 주석을 "형식 검사 시도 횟수(연결 재시도는 포함 안 됨)"로 고치거나, 정말 호출 수가 필요하면 LLMReply에 요청 횟수를 담아 합산한다.
- [제안] [확실] 401·403 오류 문구가 항상 "EXAONE_API_KEY를 확인해 주세요"로 나온다. provider=local(키 없이 쓰는 로컬 서버)이 401/403을 돌려줘도 존재하지 않는 키를 확인하라는 안내가 나와 원인 파악을 헷갈리게 한다 — 위치: backend/app/llm/openai_compat.py:138 — 확인한 범위: openai_compat.py _send_once, settings.py의 local 분기(api_key 없음) — 고치는 방법: provider가 exaone일 때만 키 안내를 붙이고, local이면 "LLM_BASE_URL · 서버 설정을 확인"으로 바꾼다.
