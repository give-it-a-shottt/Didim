- [신규] [제안] [확실] `scripts/quiz_eval.py`에 새로 넣은 두 동작에 테스트가 없다. 노트 하나의 Exception을 `generation_error`로 기록하고 다음 노트로 넘어가는 처리, `--retries` · `--pause` · `--retry-wait` 음수를 `parser.error`로 거절하는 검증. — backend/scripts/quiz_eval.py `_run`의 except 블록, `main`의 음수 검사 — diff와 패킷의 테스트 목록만 봄 — `_run`을 가짜 `evaluate_note`로 돌려 "한 노트가 터져도 나머지는 계속"을 확인하는 테스트 하나, `main`에 `--retries -1`을 주면 SystemExit(2)인지 보는 테스트 하나. 평가 스크립트라 급하지 않다.

## 체크 항목별 근거 (항목당 한 줄)
- 프론트 로딩 · 에러 · 빈 상태 → 이번 diff에 프론트 변경 없음 → 해당 없음
- 상황별 응답 코드 → notes.py `get_note` → 범위 밖 번호 404 동작 그대로(상수 이름만 변경), test_search.py parametrize가 검증. `_claim_note` 예외의 409 매핑은 이번 diff에 없어 미확인.
- 트랜잭션 롤백 → `_claim_note` → 두 갈래 모두 rollback 후 raise, IntegrityError도 rollback 후 `GenerationInProgress`, 커밋은 잠금 안에서 한 번. `save_generation` except도 rollback 먼저. 이상 없음.
- DB 제약 위반을 사용자 메시지로 → `_claim_note` IntegrityError → 409(진행 중). 이상 없음.
- 외부 API 실패 대응 → `evaluate_note`의 `except BaseException` → `abandon_generation` 후 재발생, retries 음수 보정, 정리 실패해도 선점 해제(테스트 확인). 이상 없음.
- 저장 실패 로그 → `save_generation`의 `logger.warning` → 종류 이름만, 민감 정보 없음. 로그 줄 자체의 테스트는 없음(사소해서 지적 안 함).
- 테스트 존재 · 정상/예외 → 새 테스트 5개(취소 흉내, 정리 실패 선점 해제, 음수 retries, 평가 중 예상 못 한 오류, PostgreSQL 오래된 선점 + 다른 노트 동시) → 둘 다 다룸.
- 테스트 통과 → 패킷 결과(SQLite 291/10, PostgreSQL 300/1) → 통과. 동시성 테스트는 PostgreSQL에서 통과, SQLite에서는 skip.
