# HTTP 캐시 정리

## Cache-Control max-age
응답 헤더에 `Cache-Control: max-age=3600`을 붙이면 브라우저는 그 응답을 3600초, 즉 1시간 동안 신선하다고 보고 서버에 다시 묻지 않는다. 이 시간 안에는 네트워크 요청 자체가 일어나지 않아서 개발자 도구에 "(disk cache)"나 "(memory cache)"로 표시된다.

## no-cache와 no-store
`no-cache`는 이름과 달리 저장을 막지 않는다. 저장은 하되 쓰기 전에 매번 서버에 바뀌었는지 확인하라는 뜻이다. 아예 저장하지 말라는 것은 `no-store`이고, 로그인한 사용자의 개인 정보가 담긴 응답에 쓴다.

## 조건부 요청
캐시가 만료되면 브라우저는 바로 새로 받지 않고 서버에 "바뀌었나요?"를 먼저 묻는다. 이전 응답의 ETag 값을 `If-None-Match` 헤더에 담아 보내고, 서버는 내용이 그대로면 본문 없이 304 Not Modified를 돌려준다. 그래서 큰 파일도 바뀌지 않았으면 전송량이 거의 없다.

## Last-Modified
ETag 대신 마지막 수정 시각을 쓰는 방법도 있다. 서버가 `Last-Modified` 헤더로 시각을 주면 브라우저는 다음 요청에 `If-Modified-Since`로 그 시각을 돌려보낸다. 다만 시각은 초 단위라서 1초 안에 두 번 바뀌면 구분하지 못하고, 그래서 ETag가 더 정확하다.

## 정적 파일 배포 전략
빌드할 때 파일 이름에 내용 해시를 넣는다(예: `app.3f9a1c.js`). 내용이 바뀌면 이름이 바뀌므로 이런 파일에는 `max-age=31536000`(1년)과 `immutable`을 줘도 안전하다. 반대로 HTML은 새 파일 이름을 알려 줘야 하므로 `no-cache`로 둔다.
