## 체크 항목별 근거
- 프론트 구조 → 검사 함수는 lib/report.ts에 모이고, report-data.ts는 fetch + 검사 호출만, 화면은 검사를 통과한 값만 씀. 새 상태 없음 → 적절.
- 백엔드 구조 → 범위 밖(백엔드 변경 없음).
- 데이터 → isReportRun · isReportEval · isReportMetric 칸이 RunOut · EvalOut · MetricOut과 일대일. 선택 칸은 isStringOrNull(undefined 허용)로 None 기본값과 맞고, labels_pending은 응답에 항상 실려 number 요구가 맞음. value는 null 또는 유한 숫자로 float | None과 맞음 → 일치.
- 가독성 → 함수가 짧고 이름이 역할을 말함. 죽은 코드 없음. mock의 sendJson으로 중복 제거, REPORT_MODES 표로 분기 정리. 테스트는 UNREADABLE · LANDING_CASES 표 + for로 중복을 줄임. 주석이 '왜'(서버 렌더 TypeError, 스위치 공유라 차례 실행)를 설명 → 위 제안 2개만.
- 테스트 구조 → `test.describe.configure({ mode: "default" })`와 스위치 공유 이유가 주석에 있음. `/__test/` 경로는 고장 백엔드에만 있어 일반 mock과 분리 → 적절.
- 5차 대비 → 5차 제안 2개(포트 기본값 한 곳 · 서버 순서 주석) 반영 확인.
