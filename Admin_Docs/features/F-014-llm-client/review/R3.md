## 지적
- [주의] [확실] StructuredReply.attempts가 "실제로 AI를 부른 횟수(사용량 상한을 셀 때 씀)"라고 적혀 있는데, 연결 재시도(OpenAICompatibleClient.chat 안의 2번)를 세지 않는다. 최악의 경우 AI 서버는 4번 불리는데 attempts는 2다(연결 재시도 1번만 일어나도 attempts=1인데 실제 2번). 또 앞선 시도의 토큰 수는 버려져 reply에 마지막 호출 것만 남는다. 첫 AI 기능에서 이 값으로 하루 상한(원칙 4)을 세면 실제보다 적게 센다 — 위치: backend/app/llm/structured.py:30-34, 110-124 및 backend/app/llm/openai_compat.py:81-115 — 확인한 범위: 패킷의 두 파일 전체와 테스트 — 고치는 방법: LLMReply에 http_attempts(호출 횟수)를 넣고 complete_json이 시도마다 호출 수와 토큰을 합산해 StructuredReply에 담거나, 필드 설명을 "형식 시도 횟수"로 고쳐 상한 계산에 쓰지 않게 한다.
- [주의] [확실] extract_json_text가 "첫 `{`부터 마지막 `}`까지"를 자르는 방식이라, JSON 앞이나 뒤 설명 문장에 중괄호가 있으면(예: `형식은 {key: 값} 같아요.\n{...}`) 잘못 잘려 검사에서 틀림 처리되고 재시도 한 번을 쓴다. 한국어 설명 문장에서 중괄호는 드물지 않다. 또 테스트는 plain · fenced · 앞뒤 설명(중괄호 없음) 3가지뿐이라 이 경우, 언어 표시 없는 ``` 블록, 코드 블록 앞뒤에 설명이 붙은 경우, 닫히지 않은 코드 블록, 빈 문자열, 배열 응답이 확인되지 않는다 — 위치: backend/app/llm/structured.py:37-47, backend/tests/test_llm.py:324-336 — 확인한 범위: 함수 전체와 해당 테스트 — 고치는 방법: 각 `{` 위치에서 json.JSONDecoder().raw_decode를 시도해 스키마 검사까지 통과하는 첫 객체를 쓰고, 위 경우를 parametrize 케이스로 추가한다.
- [제안] [확실] LLM_PROVIDER=mock(기본값)으로 get_llm_client()를 쓰면 기본 답이 JSON이 아니라서(`(mock) 안녕하세요...`) complete_json은 항상 LLMInvalidOutput으로 끝난다. 개발 기본값이 mock인데(D-014) 첫 AI 기능은 로컬에서 늘 실패하는 것처럼 보이고, 이 조합을 확인하는 테스트도 없다 — 위치: backend/app/llm/__init__.py:25-30, backend/app/llm/mock.py:15 — 확인한 범위: get_llm_client와 mock 전체 — 고치는 방법: 기능을 만들 때 기능별 mock 답을 넣어 주는 방법(MockLLMClient([...]))을 정하고, 지금은 "mock 기본 답은 JSON이 아님"을 mock.py 주석이나 테스트로 남긴다.
- [제안] [추정] HTTP 402(결제 · 잔액 부족) 같은 계정 문제가 "그 밖의 4xx"로 LLMRequestError("요청을 거절했어요")가 된다. 부른 쪽은 "보내는 내용을 고치라"로 읽게 되어 원인이 가려진다. EXAONE이 한도 초과 외에 402를 쓰는지는 공개 문서로 확인하지 못했다 — 위치: backend/app/llm/openai_compat.py:145-146 — 확인한 범위: 상태 코드 분기 전체 — 고치는 방법: 402를 LLMConfigError(계정 · 결제 확인)나 LLMRateLimited로 분류하고 테스트 파라미터에 추가한다. 실제 호출에서 402가 오는지 EXAONE 문서나 실호출 결과를 보면 [확실]이 된다.
- [제안] [확실] 이 모듈에는 로그가 한 줄도 없다. 연결 재시도가 일어나도, 형식 재시도가 일어나도 아무 기록이 남지 않아 나중에 "왜 느렸는지 · 비용이 왜 두 배였는지"를 알 수 없고, 평가 로그(원칙 5)도 호출하는 쪽이 전부 만들어야 한다 — 위치: backend/app/llm/openai_compat.py:104-115, backend/app/llm/structured.py:110-124 — 확인한 범위: llm 패키지 전체 — 고치는 방법: 재시도 시 logging.warning으로 이유(timeout · HTTP 503 · 형식 오류 위치)와 시도 번호만 남긴다(키 · 본문 제외). 로그를 어떻게 남길지는 첫 AI 기능과 함께 정해도 된다.
