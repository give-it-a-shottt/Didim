## 지적
- [신규] [제안] [확실] 가드의 500 갈래(`SessionConfigError` → 500 "서버 인증 설정이 완료되지 않았어요.")를 확인하는 테스트가 없다. 가드 단위 · 실제 앱 어느 쪽도 비밀키 없는 설정으로 부르지 않아, 이후 수정에서 이 갈래가 500 대신 예외로 새거나 문구가 deps와 달라져도 잡히지 않는다. — 위치: backend/app/api/upload_limit.py:102-103 (테스트는 backend/tests/test_import_markdown.py:528-546에 없음) — 확인한 범위: upload_limit.py 전문, test_import_markdown.py 전체 이름 목록 · 가드 테스트, `AUTH_NOT_CONFIGURED_DETAIL` 전체 grep(테스트 사용 없음) — 고치는 방법: `_call_guard`에 session_secret이 빈 Settings를 넘기고 서명된 쿠키 형식의 쿠키로 `(500, 0)`을 단언하는 줄 추가(상태 코드와 `AUTH_NOT_CONFIGURED_DETAIL` 문구는 응답 본문까지 보려면 `_call_guard`가 본문도 돌려주게 확장).
- [신규] [제안] [추정] Playwright의 "Esc 두 번" 시험이 `onClose` 재오픈 경로(이번 수정의 핵심)를 실제로 타는지 불확실하다. 첫 Esc는 `onCancel`의 preventDefault만 거치고, 브라우저가 두 번째에 강제로 닫는 동작은 사용자 활성화 여부에 달려 있는데 Playwright 키 입력은 사용자 조작으로 취급될 수 있어 두 번째 Esc도 막혀 버리면 `onClose`는 한 번도 불리지 않고 시험은 통과한다. 그러면 재오픈 코드를 지워도 이 시험은 초록색이다. — 위치: frontend/tests/import-records.spec.ts:131-133, 코드 import-records-dialog.tsx:82-87 — 확인한 범위: spec 전체, dialog.tsx 코드 읽기(브라우저에서 실행하지 않음) — [확실]이 되려면: 82-87의 `showModal()` 줄을 잠시 지운 상태에서 이 테스트가 여전히 통과하는지 돌려 본다. — 고치는 방법: 처리 중에 `await page.evaluate(() => document.querySelector("dialog")?.close())`로 강제 닫기를 직접 일으키고 `IMP_01_002`가 다시 보이는지 확인하는 줄을 더한다(Esc 두 번 줄은 그대로 둬도 됨).
- [신규] [제안] [추정] `test_too_many_chunks_stops_splitting_early`의 "0.5초 안에 끝남" 단언은 실행 환경 속도에 기대는 시간 비교라 느린 CI나 부하가 있는 PC에서 간헐 실패할 수 있다(주석상 끝까지 나누면 약 0.8초라 여유가 작다). — 위치: backend/tests/test_import_markdown.py:454-458 — 확인한 범위: 테스트 코드와 주석(실제 반복 실행은 하지 않음) — [확실]이 되려면: 부하 상태(다른 테스트 병렬 · CI)에서 반복 실행해 소요 시간 분포를 본다. — 고치는 방법: 시간 대신 "소비된 줄 수"로 조기 중단을 증명한다. 예: `chunking.parse_heading`을 호출 횟수를 세는 함수로 바꿔 끼우고 호출 수가 전체 줄 수(약 26만)보다 훨씬 적음(예: 상한×2 안팎)을 단언한다. 시간 단언을 유지한다면 여유를 두 배 이상으로(예: 3초 대 0.8초 기준 비교 대신 상대 비교).
