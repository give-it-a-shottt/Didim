## 지적
- [신규] [제안] [확실] 가드 500 시험이 "500 응답을 돌려줌"과 "예외가 새어 나감"을 구분하지 못한다. `_call_guard`는 `HTTPException`이 아닌 예외가 나도 `getattr(exc, "status_code", 500)`으로 500을 돌려주므로, `except SessionConfigError`가 지워져 예외가 그대로 올라와도 (500, 0)으로 통과한다. 문구(`AUTH_NOT_CONFIGURED_DETAIL`)도 단언하지 않는다. — 위치: backend/tests/test_import_markdown.py:576-579, 553-555 (코드는 backend/app/api/upload_limit.py:102-103) — 확인한 범위: upload_limit.py 90-110, `_call_guard` 전체, 해당 테스트 — 고치는 방법: `_call_guard`가 보낸 응답 본문도 돌려주게 하거나, 이 테스트만 `sent[0]["status"] == 500`과 본문 문구를 직접 단언하고 예외가 올라오면 실패하게 한다(`except` 대신 `pytest.raises` 불가 시 별도 헬퍼).
- [신규] [제안] [확실] 다시 짠 나누기에서만 생긴 분기가 직접 시험되지 않는다. (a) 한 문단이 기준을 넘은 뒤 빈 줄을 만나 `oversized`가 풀리고 다음 정상 문단이 제대로 묶이는지(chunking.py:119-122), (b) 긴 구역 안의 코드 블록 속 빈 줄이 문단 경계로 오인되지 않는지와 코드 블록 안의 `#`이 `markdown_lines(content, start, end)` 재훑기에서도 제목이 아닌지, (c) 구역 중간에서 시작하는 재훑기가 `\r` 없는 `\n` 기준으로 위치를 맞추는지. 기존 153번은 한 문단 안(짧은 줄 뒤 긴 줄)만 다루고, 140번은 정상 문단만, 131-137번 코드 블록 시험은 기준 길이 안의 구역이라 `_units`를 타지 않는다. 지금 통과하는 것은 코드가 맞아서이고, 이후 수정에서 이 분기가 깨져도 잡히지 않는다. 메모리 시험(480)도 줄이 모두 한 문단인 경우만 본다. — 위치: backend/tests/test_import_markdown.py:140-190 (대상 backend/app/services/chunking.py:108-137, 168-172) — 확인한 범위: chunking.py · markdown.py 전문, 기존 나누기 테스트 전체와 메모리 · 읽은 줄 수 시험 — 고치는 방법: `max_chars=100`으로 (1) `[긴 문단 250자(여러 줄)] + 빈 줄 + [짧은 문단]`, (2) `## 구역` 안에 코드 블록(빈 줄 · `# 주석` 포함)이 기준 길이를 넘게 들어 있는 경우를 넣고, `_assert_chunks_are_slices`와 heading_path, 그리고 "코드 블록 한 덩어리가 문단 경계에서 쪼개지지 않음"(또는 쪼개지는 위치가 줄 경계)를 단언한다. 가능하면 이전 구현의 결과를 고정값(골든)으로 한 줄 박아 둔다.
- [신규] [제안] [확실] 읽은 줄 수 시험은 "구역이 많은" 경우의 조기 중단(`_sections` 쪽)만 증명하고, "큰 구역 하나가 조각 2,000개를 넘는" 경우(`_units` · `_pack` 제너레이터)의 조기 중단은 증명하지 않는다. 후자는 이번에 새로 제너레이터가 된 경로라 `list(...)`로 되돌아가도(메모리 · 속도 퇴보) 기능 시험은 모두 통과한다. — 위치: backend/tests/test_import_markdown.py:459-477 — 확인한 범위: 해당 테스트와 chunking.py `split_markdown` — 고치는 방법: `"## 큰 구역\n" + "가\n"*N`처럼 큰 구역 하나에 대해 `max_chars`를 작게 주고(예: 10) `max_chunks`를 작게 준 뒤, `markdown_lines` 호출 수 또는 읽은 줄 수가 전체 줄 수보다 훨씬 적은지를 단언한다.
