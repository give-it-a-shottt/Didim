## 체크 항목별 근거
- 프론트 구조(컴포넌트 책임) → `note-markdown.tsx`는 "마크다운 그리기 + 범위 강조" 하나의 책임이고, 위치 변환은 lib/text-range.ts, 범위 계산 호출은 page.tsx로 나뉨. 블록 만드는 `block()` · 속성 제거 `withoutNode()` · 플러그인 `rehypeHighlightRange()`가 작게 분리됨. 강조 규칙의 "왜"(코드 블록이 조각 경계에 걸림)가 파일 머리 주석에 있음. 지적 없음. 드롭 영역은 위 [제안].
- 프론트 폴더 · architecture.md 일치 → note-markdown(32행)은 폴더 지도에 반영됨. text-range 설명만 낡음(위 [제안] 1).
- 프론트 상태 위치 → isDragging(useState) · dragDepth(useRef)는 올리기 단계 한 곳에서만 쓰는 화면 표시 상태, D-012의 "나머지는 useState"에 해당하고 architecture.md 상태 관리 지도 67행에 이유가 적힘. NoteMarkdown은 서버 컴포넌트(상태 없음). 일치.
