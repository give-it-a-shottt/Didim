# T-004 큰 업로드의 413이 Next 프록시를 거치면 연결 끊김으로 보임 (+ 확인 서버 함정 2가지)

## 한눈에 보기 (코드 몰라도 OK)
상태: [통과] 해결했어요(2026-11-10).
무슨 문제였나: 마크다운을 한 번에 너무 많이(합계 20MB 초과) 올리면 서버는 "너무 커요(413)"라고 답하는데, 화면 주소(Next.js 프록시)를 거치면 브라우저에는 그 답 대신 "연결이 끊겼어요"로만 보였어요. 사용자는 왜 실패했는지 알 수 없어요.
어떻게 해결했나: 화면이 보내기 전에 파일 개수(20개)와 합계(20MB)를 먼저 확인해서, 넘으면 보내지 않고 이유를 바로 보여 줘요. 서버의 413은 그대로 두어 마지막 방어선으로 써요.
같이 겪은 함정: 확인하는 동안 ① 끈 줄 알았던 백엔드 서버가 남아 옛 코드로 답했고, ② `next start`로 띄운 화면 서버가 빌드 때 정해진 가짜 백엔드로 요청을 보냈어요. 둘 다 "고친 게 안 먹힌다"로 잘못 볼 뻔한 문제라 같이 적어요.

## 개발자 상세

### 1. 본문을 받기 전 413 → 프록시에서 연결 끊김
- 증상: FastAPI(8000)에 22MB 요청을 직접 보내면 413과 이유가 정상으로 옴. 같은 요청을 Next 주소(`/api/notes/import`, rewrites 프록시)로 보내면 클라이언트에 `httpx.ReadError`(연결 끊김), 브라우저에서는 fetch 실패.
- 원인: 업로드 가드(`backend/app/api/upload_limit.py`)는 Content-Length가 크거나 받는 도중 상한(`MAX_IMPORT_REQUEST_BYTES` = 21MB)을 넘으면 **본문을 다 받기 전에** 413을 보내고 연결을 닫음. 서버를 지키려면 맞는 동작이지만, Next rewrites 프록시는 본문을 아직 보내는 중에 응답이 오고 연결이 닫히는 경우를 413으로 넘겨주지 않고 연결 오류로 바꿈.
- 해결: `frontend/src/lib/import-records.ts`의 `checkSelection`이 보내기 전에 개수(`MAX_IMPORT_FILES` 20) · 합계(`MAX_IMPORT_TOTAL_MB` 20MB)를 확인해 막고 문구를 보여 줌. 서버 상한(`backend/app/config.py`)과 같은 값. 서버 413은 화면을 거치지 않는 요청을 위한 방어선으로 유지.
- 다른 방법(참고, 이번엔 비교 · 시도하지 않음): 서버가 본문을 끝까지 읽은 뒤 413 → 큰 요청을 다 받아야 해서 상한을 둔 의미가 줄어듦. 프록시 대신 브라우저가 백엔드에 직접 요청 → 쿠키 · CORS 구조(F-000)를 바꿔야 해서 이번 범위 밖.
- 재발 방지: 업로드처럼 서버가 일찍 거절하는 요청은 화면에서 같은 상한을 먼저 확인한다. 상한을 바꾸면 `config.py`와 `import-records.ts`를 같이 바꾼다.

### 2. 끈 uvicorn이 남아 옛 코드가 답함
- 증상: 코드를 고친 뒤 `uv run uvicorn …`을 다시 띄웠는데 고치기 전 동작이 나옴.
- 원인: T-001과 같은 원리. 바깥 프로세스(uv)만 끝나고 자식 python(uvicorn)이 8000번 포트를 계속 잡고 옛 코드로 응답.
- 해결 · 재발 방지: 끈 뒤 `Get-CimInstance Win32_Process | ? CommandLine -match 'uvicorn'`으로 남은 프로세스를 모두 끄고, 다시 띄운 뒤 바뀐 동작 하나를 먼저 확인한다.

### 3. `next start`는 rewrites 목적지가 빌드 때 고정
- 증상: 실제 백엔드(8000)를 띄우고 `next start`로 화면을 확인했는데 요청이 실제 백엔드로 가지 않음.
- 원인: `frontend/next.config.ts`의 rewrites 목적지(`BACKEND_URL`)는 `next build` 때 정해짐. 마지막 빌드가 Playwright용이라 가짜 백엔드(`127.0.0.1:8100`, `playwright.config.ts`)를 가리키고 있었음.
- 해결 · 재발 방지: 실제 백엔드로 확인할 때는 `BACKEND_URL=http://127.0.0.1:8000 npx next dev --port 3100`처럼 dev 서버로 띄우거나, 그 값으로 다시 빌드한다.
