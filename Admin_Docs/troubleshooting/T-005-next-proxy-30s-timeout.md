# T-005 오래 걸리는 AI 요청이 Next 프록시의 30초 상한에서 끊김

## 한눈에 보기 (코드 몰라도 OK)
상태: [통과] 해결했어요(2026-11-11).
무슨 문제였나: [문제 만들기]는 AI를 기다리느라 1분이 넘게 걸리기도 해요. 그런데 화면 주소(Next.js 프록시)는 30초가 지나면 요청을 끊어서, 화면에는 실패로 보이는데 서버는 문제를 끝까지 만들어 저장하는 일이 생길 수 있었어요.
어떻게 해결했나: 프록시가 기다리는 시간을 200초로 늘렸어요. AI 호출 전체 상한(180초)에 저장할 여유 20초를 더한 값이에요.

## 개발자 상세
- 증상: 브라우저 → Next(`/api/*` rewrites) → FastAPI 구조에서 AI를 부르는 요청(F-004 `POST /api/notes/{id}/quizzes`)이 30초 언저리에서 실패로 끝남. 서버는 요청을 계속 처리함.
- 원인: Next rewrites 프록시의 기본 시간 상한이 30초다(`frontend/node_modules/next/dist/server/lib/router-utils/proxy-request.js`). AI 호출은 재시도까지 합쳐 최대 180초(`backend/app/llm/settings.py`의 전체 상한)까지 걸린다.
- 해결: [frontend/next.config.ts](../../frontend/next.config.ts)의 `experimental.proxyTimeout`을 `PROXY_TIMEOUT_MS = 200_000`(AI 상한 180초 + 저장 여유 20초)으로 설정. 이유를 주석에 남김.
- 확인: 30초 기본값은 위 Next 소스 파일에서 확인. F-004 · F-006 화면은 사용자가 직접 확인함(2026-11-11 · 12). [추정] 화면에서 30초가 넘은 실제 EXAONE 요청이 끝까지 왔는지는 따로 재서 남긴 기록이 없다 — 다시 확인하려면 개발 서버에서 [카드 후보 찾기]를 누르고 걸린 시간과 결과를 본다.
- 재발 방지: AI 전체 상한(`settings.py`)을 바꾸면 `next.config.ts`의 `PROXY_TIMEOUT_MS`도 같이 바꾼다. 배포할 때(Q-012) 앞단 프록시(Vercel 등)에도 별도 시간 상한이 있으니 다시 확인한다.
