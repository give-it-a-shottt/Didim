## 설계 의도 (사용자 확인 — 코드 작성 전에 채움, 문장 정리사 사용)
- 이 기능이 해결하는 문제 (사용자 확인 2026-11-18):
  1. 처음 온 사람은 로그인해도 빈 화면이라 무엇부터 해야 할지(기록 → 카드 → 공고) 모른다.
  2. 다시 온 사람은 오늘 복습 · 마감이 다가온 지원 · 빈칸 있는 카드를 메뉴마다 들어가서 확인해야 한다.
  3. 아직 올릴 기록이 없는 사람은 서비스를 써 볼 길이 없다.
  4. 기록 → 복습 → 카드 → 공고 → 자소서 · 면접이 한 흐름으로 이어진다는 것을 한눈에 볼 곳이 없다.
- 완료 기준 (사용자 확인 2026-11-18):
  1. 첫 방문 체크리스트(HOM_01_900): 첫 기록 · 카드 1장 · 공고 1개의 세 단계가 내 실제 데이터로 체크되고, 단계마다 그 일을 하는 화면으로 간다.
  2. 홈에 [샘플로 체험하기]가 있어 샘플 입구(`/demo`)로 간다. 누르면 내 로그인이 풀린다는 안내도 함께 보인다(D-029).
  3. 대시보드(HOM_01_001): 오늘 복습 N과 [복습 시작], 마감이 다가온 지원, 빈칸 있는 카드가 보이고, 항목을 누르면 그 화면으로 간다.
  4. 기록 → 복습 → 카드 → 공고 → 자소서 · 면접이 이어진다는 것을 홈에서 한눈에 볼 수 있다.
- 화면 · 컴포넌트 (사용자 확인 2026-11-18, `/home`, HOM_01_900 · HOM_01_001):
  - 맨 위에 단계 띠를 둔다. 기록 → 복습 → 카드 → 공고 → 자소서 · 면접 5칸이고, 칸마다 내 개수를 보여 주며, 누르면 그 화면으로 간다.
  - 첫 방문 체크리스트(첫 기록 · 카드 1장 · 공고 1개)는 세 단계를 다 끝내기 전까지 대시보드 위에 함께 보이고, 다 끝내면 사라진다. 내 데이터만 보고 정하므로 따로 저장하는 것은 없다.
  - [샘플로 체험하기]는 체크리스트가 보이는 동안에만 체크리스트 옆에 둔다. 누르면 내 로그인이 풀린다는 안내도 함께 보인다.
  - 대시보드는 오늘 복습 N과 [복습 시작], 마감이 다가온 지원, 빈칸 있는 카드 세 칸이다.
- API (사용자 확인 2026-11-18):
  - `GET /api/home`(로그인 필요): 서버가 홈에 필요한 것을 한 번에 계산해 돌려준다 — 단계 띠 개수 5개(기록 · 복습 · 카드 · 공고 · 자소서 · 면접), 오늘 복습 N, 마감이 다가온 지원 최대 4개, 빈칸 있는 카드 최대 4개.
  - 개수는 세기만 하는 가벼운 쿼리로, 요청은 한 번이다. 모든 조회에 내 사용자 ID 조건을 건다(D-004).
  - 첫 방문 체크리스트의 체크 여부는 화면이 이 개수로 판단한다.
- 데이터 (사용자 확인 2026-11-18 — 표 변경 · 마이그레이션 없음, 이미 있는 표를 세기만 한다):
  - 단계 띠 개수: 기록 = 노트 수, 복습 = 오늘 복습할 문제 수, 카드 = 저장한 카드 수(후보 제외), 공고 = 지원 수, 자소서 · 면접 = 자소서 초안을 하나라도 쓴 지원 수.
  - 첫 방문 체크리스트: 노트 1개 이상, 저장한 카드 1장 이상, 지원 1개 이상이면 그 단계가 체크된다.
  - 마감이 다가온 지원: 오늘을 포함해 7일 안에 마감이고 아직 제출하지 않은(준비 · 작성 중) 지원을, 마감이 가까운 순으로 최대 4개. 마감이 지났거나 마감일이 없는 지원은 뺀다.
  - 빈칸 있는 카드: 저장한 카드 중 빈칸이 있는 것을, 최근에 고친 순으로 최대 4장.
