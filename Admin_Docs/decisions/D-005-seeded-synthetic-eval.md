# D-005 평가는 "정답을 미리 심어 둔 가상 데이터"로 한다

## 한눈에 보기 (코드 몰라도 OK)
상태: [통과] 사용자가 골랐어요(2026-11-07).
무엇을: 가상 지원자의 경험 카드와 가상 공고를 만들 때, 어떤 카드가 어떤 공고 역량에 맞는지를 먼저 정해 두고 글을 써요. 자소서 초안에는 일부러 지어낸 문장을 섞어 넣고, 검사기가 몇 개를 잡는지 세요. 같은 데이터를 첫 방문 "샘플 체험"에도 써요.
왜: 혼자 정답을 매기면 표본이 작고 내 쪽으로 기울어서 면접관이 수치를 믿기 어려워요. 정답을 만들 때부터 심어 두면 매기는 사람의 판단이 들어가지 않아요.

## 개발자 상세

### 후보
| 후보 | 장점 | 단점 |
|---|---|---|
| A. 정답을 심어 둔 가상 데이터 (선택) | 라벨 편향 없음, 샘플 체험과 데이터 공유 | 가상 데이터가 실제 분포와 다를 수 있음 |
| B. 실제 공고 + 혼자 라벨링 | 현실적 | 표본 작음 · 자기 편향(기획 검수 회의론자 지적) |
| C. 실제 공고 + 동기 1~2명 교차 라벨링 | 일치율 공개 가능 | 시간 · 사람 필요 |
| D. 평가 빼기 | 일이 줄어듦 | 핵심 목적(수치로 증명)이 사라짐 |

### 결정
- A. 가상 카드 20장 · 가상 공고 10개, 공고별 정답 카드를 먼저 정한다.
- 초안 탐지 평가: 문장 10개 중 3개 정도를 일부러 지어낸 문장으로 섞는다.
- 퀴즈 평가: 정답이 정해진 가상 노트에서 문제를 만들고 원문과 비교한다.
- 측정: 매칭 상위 3 적중률, 근거 없는 문장 탐지율, 퀴즈 정답 · 해설 일치율. 결과는 평가 리포트(SET_02_001)와 README 표.
- 실제 내 기록으로 돌린 결과는 "참고 사례"로만 따로 보여 준다.
- 평가 틀은 포트폴리오 검색 개선 때 쓴 시험지 · 채점기 구조(queries · run · runs/)를 재사용한다.
