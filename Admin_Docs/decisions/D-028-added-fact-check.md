왜 (사용자 선택): 추천안 A(프롬프트 + 규칙 검사)와 '확인 필요' 표시를 골랐어요.

|---|---|---|

### 결정
- 프롬프트: 빈 칸도 보내되 '기록 없음 — 이 칸 내용을 지어내지 말 것'으로 표시한다(지금은 빈 칸을 아예 빼고 보냄 — `draft_writing.build_draft_messages`).
- 검사: 근거가 붙은 모든 문장(AI 근거 · [카드 연결] 근거)에 R1 · R3를 돌린다. 걸리면 근거(카드 · 칸 · 인용)는 그대로 두고 '확인 필요'와 이유(카드에 없는 숫자 · 낱말, 또는 '결과 기록이 없는 카드에 성과 표현')를 보여 준다.
- 계산 시점: 지금 근거 상태처럼 저장하지 않고 읽을 때 계산한다(카드에 결과 칸을 나중에 채우면 경고가 저절로 사라짐).
- 화면 · 해제 (F-008 설계 의도, 사용자 선택 2026-11-16): 근거 칩과 함께 '확인 필요' 경고. 문장을 고치면 다시 계산하고, 잘못 경고면 [확인함]으로 끈다. '제출'로 바꿀 때 확인창에 '확인 필요 N개'를 같이 알린다(막지 않음).
- AI를 더 부르지 않는다(원칙 4). 규칙이라 평가 수치가 판정 흔들림 없이 재현된다(D-005).
- 저장: [확인함]을 누를 때 걸려 있던 이유(예: `unknown_token:40|result_without_record`)만 문장에 칸 하나로 저장(`confirmed_claims`, Alembic 0010, D-015). 읽을 때 지금 이유와 같아야 '확인함' — 카드가 바뀌어 이유가 달라지면 다시 경고(Q-029, 사용자 선택 2026-11-17).
- [확인함] · [확인 풀기]는 따로 된 요청(`PATCH /api/drafts/{id}/sentences/{sid}`)으로 저장하고 완료 표시를 지우지 않는다(Q-028, 사용자 선택 2026-11-17). version은 올려 옛 화면의 문장 저장이 확인을 덮어쓰지 않게 한다.
- R3 표현 목록에서 '방지했' · '개선했'을 뺐다 — 행동 설명에도 써서 잘못 경고(사용자 선택 2026-11-17). 표현 목록을 바꾸는 것은 사용자가 정한다(7차 리뷰 R4).
