## 면접 예상 질문
1. 스크롤 애니메이션을 스크롤 위치에 바로 묶지 않고 '장면 번호 + CSS transition'으로 만든 이유는? 빠르게 스크롤할 때는 어떻게 되나요?
   - 답 (2026-11-19):
     - 처음에는 스크롤한 만큼 투명도 · 위치 값을 바로 바꿨는데, 스크롤 이벤트는 휠 한 번에 값이 뚝뚝 끊겨 들어와서 화면도 끊겨 보였어요. 그래서 스크롤은 '지금 몇 번째 장면인가'만 정하고, 실제 움직임은 CSS transition에 맡겼어요.
     - 고정 구간(250vh) 안에서 스크롤 진행률을 세 칸으로 나눠 목표 장면을 정하고, 섹션의 `data-step` 속성만 바꿔요. 장면이 바뀌면 CSS가 600ms ease-out으로 투명도와 가로 8px 이동을 부드럽게 이어 줘요. 스크롤 값은 `requestAnimationFrame`으로 한 프레임에 한 번만 재요.
     - 빠르게 스크롤해서 1장에서 3장으로 바로 가도 한 번에 건너뛰지 않아요. 0.35초 간격으로 한 칸씩 넘겨서 2장이 반쯤 들어온 뒤에 3장이 들어와요. 이야기 순서가 '문장 → 근거 없음 표시 → 빼고 원문 각주'라서, 중간 장면을 건너뛰면 무엇이 바뀌었는지 안 보이기 때문이에요.
     - 전환 선언(`transition`)은 기본 선택자에 두고, 상태 선택자에는 값만 바꿨어요. 그래야 들어올 때와 나갈 때 같은 속도로 움직여요.
2. 랜딩은 서버 컴포넌트가 기본인데 클라이언트 컴포넌트는 어디에만 썼고, JS가 꺼져 있거나 움직임 줄이기 설정이면 화면이 어떻게 보이나요?
   - 답 (2026-11-19):
     - 클라이언트 컴포넌트는 두 개뿐이에요. 스크롤 위치를 읽어 장면 번호를 정하는 `LandingPinnedScenes`와, 아래 구역 칸이 화면에 들어올 때 떠오르게 하는 `LandingReveal`(IntersectionObserver)이에요. 브라우저에서만 알 수 있는 스크롤 · 화면 진입을 다뤄야 해서요.
     - 장면 글 · 기능 카드 · 자소서 예시 같은 내용은 전부 서버에서 그려서 `children`으로 넘겨요. 그래서 검색 로봇과 JS가 없는 브라우저도 글을 다 읽을 수 있고, 브라우저로 보내는 JS도 작아요.
     - 움직임은 'JS가 돈 뒤에 붙는 속성'에만 걸었어요. 고정 구간은 JS가 `data-motion`을 붙여야 250vh가 되고, 떠오름은 JS가 `data-reveal="pending"`을 붙여야 숨겨져요. 그래서 JS가 꺼져 있으면 세 장면이 나란히 다 보이는 정지 화면이 되고, 숨겨진 채 남는 글이 없어요.
     - 움직임 줄이기 설정이면 CSS에서 고정 구간과 떠오름을 `prefers-reduced-motion: no-preference`일 때만 켜기 때문에, 역시 다 보이는 정지 화면이에요. 좁은 화면도 고정하지 않고 세 장면을 다 보여 줘요. 움직임 줄이기 화면은 Playwright로 확인했어요.
3. 랜딩 첫 화면 평가 수치를 코드에 적지 않고 리포트 API에서 읽는 이유와, 못 읽을 때의 처리는?
   - 답 (2026-11-19):
     - 디딤의 원칙이 '근거 우선'이라, 랜딩 수치도 실제로 잰 값이어야 했어요. Figma 시안에는 90% 같은 예시 숫자가 있었지만 쓰지 않았어요. 평가를 새로 돌리면 `/report` 화면, README 표, 랜딩이 모두 같은 요약 파일을 읽어서 숫자가 서로 어긋나지 않아요.
     - 사람 판정이 필요한 수치는 판정이 끝날 때까지 숫자 대신 '판정 대기'로 보여 주고, 그 회차에 돌리지 못한 평가는 칸을 빼요. 수치 아래에는 회차 날짜 · 모델 · 가상 데이터 규모를 같이 적어요.
     - 수치 부분만 Suspense 안에서 읽어서, 백엔드가 느려도 첫 화면의 나머지는 먼저 보여요. 못 읽으면 수치 칸만 숨기고 [평가 리포트 전체 보기] 링크는 남겨요. 랜딩의 첫 목적은 서비스를 소개하는 것이라 수치 때문에 페이지가 깨지면 안 되기 때문이에요.
     - '못 읽음'에는 서버 연결 실패, 500, JSON이 아닌 응답, 모양이 틀린 응답이 다 들어가요. 처음에는 `runs`가 배열인지만 확인해서, 회차 안쪽 모양이 틀리면 서버 렌더가 통째로 터졌어요. e2e로 이걸 잡고 회차 · 평가 · 수치 모양까지 검사하게 고쳤어요. 화면 서버가 백엔드를 직접 불러서 `page.route`로는 못 가로채기 때문에, 고장 난 가짜 백엔드를 보는 화면 서버를 하나 더 띄워 테스트해요.
     - 캐시는 일부러 안 붙였어요(D-030). `"use cache"`를 쓰면 빌드 때 읽은 값이 정적 화면에 들어가는데, 그때 백엔드가 꺼져 있으면 '못 읽음'이 굳어 버려요. 배포 방식을 정할 때 다시 보려고 해요.
