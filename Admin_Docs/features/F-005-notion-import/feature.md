# F-005 노션 연결

## 한눈에 보기 (코드 몰라도 OK)
상태: [주의] 설계 의도를 받았어요(2026-11-12). 다음은 구현이에요.
언제: 4주차
무엇을: 설정에서 노션을 한 번 연결하고(OAuth), 기록 추가의 노션 탭에서 페이지를 골라 가져와요. 마크다운으로 바꿔 F-002와 같은 경로로 저장해요. 토큰이 끊기면 설정에서 재연결
왜: 노션에 정리하는 사람이 페이지마다 내보내기를 거치지 않게 하려고요.

## 설계 의도 (사용자 확인 — 코드 작성 전에 채움, 문장 정리사 사용)
- 이 기능이 해결하는 문제: 노션에 공부 기록을 정리하는 사람에게는 페이지를 하나하나 마크다운으로 내보내 올리는 일이 번거롭다. 노션을 한 번 연결해 두면 내보내기 없이 페이지를 골라 바로 가져오게 한다. (사용자 확인, 2026-11-12)
- 정한 것 (사용자 선택, 2026-11-12):
  - 연결: 노션 공개 통합 OAuth. 토큰 쌍(접근 · 갱신)을 암호화해 저장, 만료되면 자동 갱신(갱신 때 갱신 토큰도 새것으로 바뀌어 매번 저장), 갱신이 실패하면 '끊김' → 설정에서 재연결. 개발은 `http://localhost:3000/api/notion/callback`(노션은 http를 localhost에만 허용, 127.0.0.1 안 됨) — 배포 없이 연결 가능.
  - 가져오기: 한 번 가져오기 + 중복 안내(F-002와 같음). 노션에서 고친 내용 반영(다시 가져오기)은 2차 — 기존 퀴즈 · 카드 인용 위치가 깨지지 않게.
  - 하위 페이지: 고른 페이지만(페이지 하나 = 노트 하나). 하위 페이지는 목록에서 따로 고른다.
  - 구조(D-001): 노션 블록 → 마크다운 글로 바꾼 뒤 F-002의 나누기 · 저장 경로에 넣는다. 검색 · 퀴즈 · 카드는 바꾸지 않는다. AI 호출 없음.
  - 변환: 제목 · 문단 · 목록 · 할 일 · 인용 · 콜아웃 · 코드 · 토글(안쪽까지) · 구분선 · 표(글자만). 이미지 · 파일 · 임베드 · 데이터베이스 · 하위 페이지는 건너뛰고 "건너뛴 블록 N개" 안내. 노션 호출 간격(초당 약 3번)과 페이지당 블록 수 상한.
- 완료 기준(무엇이 되면 끝인지): (사용자 확인, 2026-11-12)
  1. 설정에서 노션 연결 · 끊기, 상태(연결됨 · 끊김 · 워크스페이스 이름) 표시
  2. 토큰이 만료되면 자동 갱신, 갱신 토큰이 무효면 '끊김'으로 바꾸고 재연결 안내 · 노션 일시 장애면 연결은 두고 잠시 후 다시 (문구 조정 — 사용자 확인 2026-11-12, F-005 2차 리뷰)
  3. 노션 탭에서 페이지를 골라 가져오면 노트 + 조각이 생김(출처 노션)
  4. 이미 가져온 페이지 · 같은 내용이면 중복 안내
  5. 다른 사용자의 토큰 · 페이지가 섞이지 않음(D-004)
  6. 노션 API는 가짜 서버로 테스트 — 실제 노션 없이 테스트 통과
- 화면 · 컴포넌트: 설정(SET_01_001) '연결' 칸의 노션 줄 — 연결 전 [연결] · 연결 뒤 워크스페이스 이름 + [연결 끊기] · 끊김 "연결이 끊겼어요 · 권한이 만료됐어요" + [다시 연결] (Figma 28:1273 문구에 맞춤 — 사용자 확인 2026-11-12, 3차 리뷰). 기록 추가 모달(IMP_01_001) 노션 탭 — 연결 전이면 설정 안내, 연결 뒤 공유된 페이지 목록(제목 · 수정일 · '이미 가져옴')에서 골라 [가져오기] → 결과 요약(F-002와 같음).
- API: `GET /api/notion/connect`(노션 동의 화면으로, state 쿠키는 F-001 방식) · `GET /api/notion/callback`(코드 → 토큰 저장 → `/settings`) · `GET /api/notion/status` · `DELETE /api/notion/connection`(토큰 삭제, 가져온 노트는 남김) · `GET /api/notion/pages` · `POST /api/notion/import`(고른 페이지 최대 20개 + 기록 종류 `kind`, 응답 모양은 F-002와 같음)
- 데이터: 버전 파일 0006 — `notion_connections`(사용자당 1개 CASCADE, 워크스페이스, 접근 · 갱신 토큰 암호화, 만료 시각, 상태), `notes.notion_page_id`(사용자 + 페이지 유니크 — '이미 가져옴' · 중복 기준). 토큰 암호화는 `cryptography`(Fernet) 패키지 추가, 키는 `.env` 새 값(R2 리뷰 대상).
- 사용자 할 일: 노션 개발자 페이지에서 공개 통합 등록 → 리디렉트 주소 등록 → client ID · secret을 `backend/.env`에. 등록 전에도 가짜 서버 테스트로 구현은 끝낼 수 있다.
- 참고: 예전에 마크다운으로 올린 노션 경험 카드 노트 10장은 같은 페이지를 노션으로 가져와도 변환 글자가 달라 중복으로 안 잡힌다.

## 결과 (AI 작성 — 구현 후)
- 서버: `app/api/notion.py`(API 6개, 노션 호출이 동기라 동기 엔드포인트), `app/notion/client.py`(HTTP만 — 토큰 교환 · 갱신은 HTTP Basic, 검색 · 페이지 · 블록 읽기는 `Notion-Version: 2026-03-11`, 요청 사이 0.34초, 429는 Retry-After(최대 10초) · 5xx · 연결 실패는 2번까지 다시), `app/importers/notion.py`(블록 나무 → 마크다운 글, 순수 함수), `app/services/notion_service.py`(연결 저장 · `NotionSession` 토큰 갱신 · 페이지 목록 · 가져오기), `app/services/token_crypto.py`(Fernet). 노트 저장은 F-002와 같은 `split_markdown` · `create_note_for_user`(`notion_page_id` 인자 추가). state는 `auth_service.create_notion_state_token` — 연결을 시작한 사용자 번호를 담아 콜백 때 지금 로그인한 사용자와 같은지 확인(다른 사용자의 연결이 내 계정에 붙지 않게).
- 토큰: 만료 시각(`expires_in`)을 주면 60초 전에 미리 갱신, 안 주면 401을 받았을 때 한 번 갱신 뒤 다시. 갱신이 `invalid_grant`면 '끊김'(토큰 지움). 노션은 갱신할 때 갱신 토큰도 바꾸므로, 연결 줄을 잠근(FOR UPDATE) 뒤 "그새 다른 요청이 바꿨는지" 보고 바뀌었으면 그 토큰을 쓴다(동시 갱신으로 멀쩡한 연결이 끊기지 않게). 암호화 키가 바뀌어 토큰을 못 풀어도 '끊김'.
- 가져오기 상한(`app/config.py` `NOTION_*`): 한 번에 20페이지, 목록 100개, 페이지당 블록 2,000개, 안쪽 깊이 6, 시간 예산 150초(Next 프록시 200초 안 — T-005). 넘으면 그 페이지만 실패하고 이유를 알려 줌. 도중에 연결이 끊기면 저장한 페이지는 남기고 `connection_broken`.
- 데이터: 버전 파일 0006 — `notion_connections` + `notes.notion_page_id`. (사용자, 페이지) 중복 막기는 유니크 **제약 대신 유니크 색인** — SQLite에서 제약을 더하면 notes를 다시 만들며 CASCADE로 조각이 지워지는 것을 마이그레이션 테스트로 발견(되돌리기도 표를 다시 만들지 않게 `op.drop_column`). 개발 DB에 0006 적용(2026-11-12).
- 화면: 설정 '연결' 칸(`components/notion-connection-row.tsx`, Figma 28:1273 — 연결 전 [연결] · 연결됨 워크스페이스 + [연결 끊기] · 끊김 경고 + [다시 연결]), 연결 뒤 돌아온 안내(`?notion=connected` · `?notion_error=`). 기록 추가 모달 노션 탭(`import-records-dialog.tsx` NotionPicker — 페이지 목록 `useQuery`, 최대 20개 고르기, '이미 가져옴'은 못 고름, 409 · 503이면 설정 링크). 결과 요약은 마크다운과 같이 쓰고 건너뛴 블록 수 · 도중 끊김 안내를 더함. 요청은 `lib/notion.ts`(브라우저) · `lib/notion-data.ts`(서버). 아이콘 `warning` 추가(Figma에서 받음).

- 1차 리뷰 반영(2026-11-12, 사용자 선택 — 주의 전부 + 제안 대부분):
  - 버그 · 예외: 페이지를 읽는 도중 예산을 넘으면 그 페이지가 실패 목록에 두 번 들어가던 것(제목과 함께 한 번), 검색 403 · 도중 다른 창에서 끊기가 500이던 것(502 이유 문구 · `connection_broken`). 노션 오류 → HTTP 응답은 `api/notion.py`의 `_http_error` 한 곳.
  - 시간 · 자원: 시간 예산을 노션 호출 하나 안에서도 지킴(`NotionClient.set_time_budget` — 요청 시간 상한 · 재시도 대기를 남은 시간으로 자름, 프록시 200초 안). 노션을 부르는 동안 DB 트랜잭션을 닫음. 사용자당 가져오기 하나(`notion_connections.importing_since`, 이미 돌면 409, 5분 지나면 새 요청이 가져감 — 사용자 선택). 0006은 커밋 전이고 개발 DB 노션 데이터가 0건이라 새 버전 파일 대신 0006을 고쳐 다시 적용.
  - 보안: 토큰 교환 · 갱신 요청은 다시 보내지 않음(갱신 토큰 교체 때문에 재전송이 invalid_grant → 끊김이 될 수 있음), 두 번째 401은 줄을 잠그고 그새 다시 연결했는지 본 뒤 끊김, 응답의 블록 번호도 형식 검사 뒤 주소에, 페이지 번호 한 개 64자까지, OAuth state 비교 전 ASCII 확인(구글 로그인 state 확인도 같이 — 비ASCII가 500이던 것), [연결 끊기] 때 노션 토큰 회수 시도(`POST /v1/oauth/revoke`, 실패해도 넘어감), 비로그인으로 연결 · 콜백 주소를 열면 /login(사용자 선택).
  - 화면: 목록이 100개를 넘으면 '최근 100개만' 안내(`truncated`), 노션 목록 다시 받기 줄이기(1분 · 창 포커스 끔), 마크다운 탭을 `MarkdownPicker` · 드래그를 `useFileDrop`로 분리, 중복 문구 노션일 때 '이미 가져온', 상태 · 안내 문구를 `lib/notion-status.ts`로(서버 컴포넌트가 브라우저 요청 모듈을 가져오지 않게), 응답에 노트 번호가 없으면 0으로 채우지 않고 오류.
  - 구조: 실패 기록 도우미 `_fail`, 페이지 읽기 `_read_page` 분리, 연결 상태 `ConnectionState` 타입(라우터의 `type: ignore` 없앰), 번호 정리를 서비스 `normalize_page_ids`로, 응답 조립 `_import_out`, `NOTION_PAGE_ID_LENGTH`를 모델에서 씀.
