# F-006 경험 카드 — 후보 뽑기 · 빈칸 질문 · 근거

## 한눈에 보기 (코드 몰라도 OK)
상태: [주의] 설계 의도를 받았어요(2026-11-11). 다음은 구현이에요.
언제: 4주차
무엇을: 기록에서 상황 · 과제 · 행동 · 결과 카드 후보를 뽑고, 사용자가 하나씩 확인해 저장해요. 빈칸은 AI가 질문만 하고 답은 사용자가 써요
왜: 오래돼서 잊은 경험도 기록에서 찾아 꺼내, 자소서에 쓸 기술 스택 · 경험을 놓치지 않게 하려고요.

## 설계 의도 (사용자 확인 — 코드 작성 전에 채움, 문장 정리사 사용)
- 이 기능이 해결하는 문제: 오래된 경험은 기억에서 잊혀서, 공부 기록에 남아 있어도 자소서에 쓰지 못한다. 내 기록에서 경험 카드 후보를 찾아 꺼내 주어, 잊었다는 이유로 기술 스택이나 경험을 놓치지 않게 한다. AI는 기록에 있는 것만 찾아 주고 지어내지 않는다. (사용자 확인, 2026-11-11)
- 정한 것 (사용자 확인, 2026-11-11 — 선택지로 받음):
  - 카드에는 사용자 답과 근거만 저장한다(D-003 그대로). AI가 내 답을 다듬은 문장은 카드에 저장하지 않는다.
  - 후보 = 칸별 원문 인용: AI가 노트에서 경험 하나를 찾으면 상황 · 과제 · 행동 · 결과 칸마다 노트 문장을 글자 그대로 골라 준다. 서버가 그 문장이 원문에 글자 그대로 있는지 확인하고, 없으면 그 칸은 빈칸으로 둔다. 빈칸은 AI가 질문만 하고 답은 사용자가 쓴다.
  - 찾는 단위: 노트 상세의 [카드 후보 찾기]로 노트 하나씩, AI 호출은 노트당 한 번(F-004와 같은 구조). 기록 전체 훑기는 Q-008을 정한 뒤.
  - 노트당 후보 최대 3개(config 상수, 평가 뒤 조정).
  - 찾은 후보는 DB에 '후보' 상태로 저장해 두고 나중에 검토 · 저장 · 버리기(시트를 닫아도 남아 AI를 다시 부르지 않음).
  - 빈칸 질문은 후보를 찾을 때 같은 AI 호출에서 빈칸마다 하나씩 받는다. 질문은 카드 본문이 아니라 따로 저장하고 화면에만 보여 준다.
  - 계정에 이미 올라간 노션 경험 카드 노트 10장은 따로 변환하지 않고 일반 노트처럼 [카드 후보 찾기]로 카드를 만든다.
  - 카드는 후보에서만 생긴다(AI 없이 빈 카드 직접 만들기는 이번에 넣지 않음 — 모든 카드에 노트 근거가 있게).
  - 인용 칸: 인용(근거)은 고칠 수 없고, 그 아래에 내 답을 덧붙여 쓴다. 잘못 골라진 인용은 [인용 빼기]로 지우면 빈칸이 된다.
  - 카드 제목: 후보에 AI가 제목을 붙이고, 저장할 때 사용자가 그대로 쓰거나 고친다. 제목은 이름표일 뿐 자소서 근거로 쓰지 않는다(근거는 칸 내용만).
- 완료 기준(4주차): (사용자 확인, 2026-11-11)
  1. 노트 상세 [카드 후보 찾기] → AI 1번 호출, 후보 최대 3개. 칸마다 원문 인용(글자 그대로 검사, 없으면 빈칸) + 빈칸마다 질문 1개. 이미 후보를 찾은 노트면 AI를 부르지 않고 409.
  2. 후보는 DB에 '후보'로 저장. 후보 검토 시트(CRD_01_003)에서 하나씩 [저장] · [버리기].
  3. 카드 목록(CRD_01_001): 빈칸 수 · 근거 수 · 수정일, 카드가 없으면 빈 상태(900).
  4. 카드 상세(CRD_01_002): 인용 칸은 명조 원문 + 근거 칩(노트 위치 강조), 빈칸은 AI 질문 + 내 답 입력 · 저장. 빈칸 0개면 완성.
  5. 카드에는 원문 인용 · 사용자 답 · 근거 링크만 저장(AI 문장 없음) — 테스트로 확인.
  6. 모든 조회에 사용자 ID 조건, 다른 사용자 노트 · 카드는 404. 하루 AI 상한(D-018)은 퀴즈와 공유.
  7. 평가(D-005): 경험을 심어 둔 가상 노트 + 경험 없는 노트로 찾은 비율(심은 경험 중 찾은 수) · 없는 경험으로 만든 후보 수 · 인용 검사로 빈칸이 된 칸 비율을 재고 로그로 남긴다.
- 화면 · 컴포넌트: (사용자 확인, 2026-11-11)
  - 노트 상세: [카드 후보 찾기] + "후보 N개 검토" 링크 → 후보 검토 시트(CRD_01_003, 하나씩 제목 확인 · [저장] · [버리기]).
  - `/cards`(CRD_01_001): 탭 후보 · 내 카드, 카드마다 빈칸 수 · 근거 수 · 수정일, 빈 상태(CRD_01_900).
  - `/cards/[cardId]`(CRD_01_002): 네 칸 — 인용(명조) + 근거 칩, 빈칸 질문, 내 답 입력.
- API: (사용자 확인, 2026-11-11)
  - `POST /api/notes/{id}/cards/candidates` 후보 찾기(AI 1번) — 409 이미 찾음 · 찾는 중, 429 하루 상한, 502 · 503 AI 실패
  - `GET /api/cards?status=candidate|saved` 목록 · `GET /api/cards/{id}` 상세
  - `POST /api/cards/{id}/save` 후보 → 저장(제목 포함) · `DELETE /api/cards/{id}` 버리기 · 삭제
  - `PUT /api/cards/{id}/fields/{slot}` 내 답 저장 · 인용 빼기
- 데이터 (버전 0005, 사용자 확인 2026-11-11):
  - `cards`: 사용자, 후보를 찾은 노트(`SET NULL` — 노트가 지워져도 카드는 남음), 제목, 상태(candidate · saved), 수정일.
  - `card_fields`: 카드마다 4줄(situation · task · action · result, 카드+칸 유니크). 원문 인용 · 위치 · 조각(`SET NULL`), AI 빈칸 질문, 내 답을 따로 둔다. 빈칸 = 인용도 답도 없음, 근거 수 = 인용 있는 칸 수, 빈칸 0개 = 완성. (처음 계획한 `card_evidence`는 근거가 칸 단위라 여기에 합침)
  - `note_card_claims`: F-004와 같은 선점(노트 유니크) — 동시 클릭에도 AI 한 번, 이미 찾은 노트는 409.
  - `card_generation_logs`: 평가 로그 — 보낸 조각 수, 후보 수, 인용 칸 수, 인용 검사로 빈칸이 된 칸 수, 결과(완료 기준 7).
  - AI가 정할 임시값(리뷰 때 사용자 확인): 노트당 보내는 조각 · 글자 상한, 인용 최소 길이.
