## 지적 (있을 때)
- [신규] [제안] [확실] 다른 탭에서 먼저 만들어 409가 나온 뒤 카드 다시 받기까지 실패하면, 그 실패 안내가 화면에 안 나온다. refreshFailed 문구는 `makeQuestions.data`가 있을 때만 붙는데 409는 data 없이 error라서다. 사용자는 "이미 면접 질문이 있어요"만 보고, 질문 목록은 비어 있고 버튼은 계속 보인다. 다시 누르면 같은 409만 나온다. — frontend/src/components/card-editor.tsx (makeQuestions.onError · refreshFailed 표시부) — 패킷 diff 전체 — 고치는 방법: refreshFailed 문구를 `makeQuestions.data` 분기 밖으로 빼서 error일 때도 보여 주거나, 409 안내에 "새로 고침해 확인해 주세요"를 같이 붙인다.
- [신규] [제안] [확실] 메모 PATCH 본문 크기 상한 422(MemoIn max_length = 2,000 x 5 = 10,000자 초과, pydantic 기본 422)를 확인하는 테스트가 없다. 테스트는 서비스 상한(2,001자)과 제어 문자만 본다. 이 경로는 detail이 문자열이 아니라 pydantic 오류 목록이다. 화면(RequestErrorText)이 목록 모양 detail을 어떻게 보여 주는지도 확인되지 않았다. — backend/tests/test_interview.py `test_memo_saves_clears_and_validates` · backend/app/api/interview.py `MemoIn` — 확인한 범위: 패킷의 테스트 코드와 API 코드(frontend/src/components/request-error.tsx는 열지 않음) — 고치는 방법: `"가" * 10_001`로 422를 확인하는 한 줄을 더한다. 화면 쪽은 request-error 코드를 열어 목록 모양 detail을 처리하는지 본다. 다른 기능의 같은 패턴에서 이미 확인했다면 생략해도 된다.
- [신규] [제안] [확실] 2차 반영의 핵심(선점 뒤 `db.rollback()`, 합치기 전 질문 유무 `has_questions`)이 PostgreSQL에서는 이번에 안 돌았다(Docker 꺼짐, 직전 547 passed는 2차 반영 전). SQLite는 트랜잭션 · 행 잠금 동작이 달라 "idle in transaction" 해소와 선점 유니크 경합은 PostgreSQL에서만 의미 있게 확인된다. — 패킷 '테스트 결과' — 고치는 방법: 커밋 전에 PostgreSQL로 `uv run pytest -q`를 한 번 돌려 결과를 STATUS에 남긴다. 그 전에는 "PostgreSQL 미확인"으로 적어 둔다.
- [신규] [제안] [추정] `prepare_interview`에서 `claim_target` 성공 뒤(두 번째 `_has_questions` · `release_claim` · `db.rollback()`) DB 오류가 나면 선점이 풀리지 않는다. 엔드포인트의 `try`는 `prepare_interview` 예외를 `_PREPARE_ERRORS` 표로만 처리하고 `abandon`을 부르지 않는다. 그러면 사용자는 5분(INTERVIEW_CLAIM_STALE_SECONDS) 동안 "만드는 중" 409를 받는다. 확률은 낮고 5분 뒤 자동 회복된다. — backend/app/services/interview_service.py `prepare_interview` · backend/app/api/interview.py `write_interview_endpoint` — 확인한 범위: 패킷 코드. 다른 AI 기능(drafts 등)이 같은 구조인지는 안 봤다 — [확실]이 되려면 같은 위치에 DB 오류를 주입해 선점 줄이 남는지 테스트로 본다. 고치는 방법: 선점 뒤 코드를 try로 감싸 실패 시 `note_claim.release_claim`을 부른다. 저장 · 실패 처리 공통화를 미루기로 했으니 그때 같이 해도 된다.
