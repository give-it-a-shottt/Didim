(선점·세션 조율을 서비스로 옮기는 큰 정리와는 별개인 작은 이동)
- [신규] [제안] [확실] `_import_one` 길이와 분기 수 — backend/app/services/notion_service.py 594~657줄(약 65줄, 종료 분기 7개) — 함수 전체 읽음 — 한 함수에 "이미 가져옴 확인 → 읽기 → 변환 → 내용 중복 → 나누기 → 저장 + 경쟁 중복 처리"가 모두 있어 흐름을 한눈에 따라가기 어렵다. 나누기+저장 구간(614~657줄)을 `_save_page(page_id, rendered)`로 빼고 `_import_one`은 단계 호출만 남기면 된다. 동작은 그대로라 기존 테스트로 확인 가능.
- [신규] [제안] [확실] 가변 리스트를 숫자 세는 데 씀 — backend/app/services/notion_service.py `_read_page`의 `[0]`(555줄)과 `_fetch_tree(..., counter: list[int], ...)`(566줄, `counter[0] += 1`) — 두 함수 읽음 — 읽는 사람이 "왜 리스트인가"를 추측해야 한다. `_Importer`의 속성(`self._block_count`)을 `_read_page` 시작에서 0으로 두고 `_fetch_tree`가 올리게 하면 인자가 하나 줄고 `[0]`이 사라진다.
- [신규] [제안] [확실] 구글 state 확인과 노션 state 확인이 같은 앞부분을 복붙 — backend/app/services/auth_service.py `verify_oauth_state_token`(162~167줄)과 `verify_notion_state_token`(347~352줄) — diff로 두 함수 읽음 — 빈 값 검사 · ASCII 검사 · `compare_digest`가 똑같아, 한쪽 보안 수정(1차 때 ASCII 검사가 이렇게 두 곳에 들어감)이 다른 쪽에서 빠질 수 있다. `_states_match(query_state, cookie_state) -> bool` 도우미로 빼서 둘이 부르게 한다.
