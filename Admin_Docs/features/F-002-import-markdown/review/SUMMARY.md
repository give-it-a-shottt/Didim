## 신규 지적
- P. [신규] [주의] [확실] 조각 상한은 "조각 수"만 멈춰서, 한 구역(제목 사이)에 줄이 아주 많은 1MB 파일은 상한 안에서 정상 저장되면서도 파일 하나에 약 180MB 메모리 · 2초 넘는 CPU를 씀 — R2. 원인: `_sections`가 구역의 모든 줄을 `MarkdownLine` 객체로 쌓고, 큰 구역이면 `_paragraphs` · `_units`가 줄마다 목록을 또 만듦. `find_title`도 1단계 제목이 없으면 줄 객체를 끝까지 만듦. 고치는 방법: 구역을 줄 목록 대신 위치(시작 · 끝)로 들고 다니고, 기준 길이를 넘는 구역만 그 구간을 다시 훑으며 조각을 흘려보냄. `backend/app/services/chunking.py`, `backend/app/importers/markdown.py`
- Q. [신규] [제안] [확실] 세션 쿠키 앞부분에 ASCII가 아닌 바이트가 있으면 로그인 없이 500 + ERROR 로그 — R2. F-001 코드(`auth_service._verify_payload`가 `encode("ascii")`를 try 밖에서 부름)라 로그인이 필요한 모든 API에 해당. 응답에 내부 정보는 없음. 고치는 방법: 맨 앞에서 `token.isascii()`가 아니면 None.
- R. [신규] [제안] [확실] 가드의 500 갈래(인증 설정 오류) 테스트 없음 — R3.
- S. [신규] [제안] [추정] Playwright "Esc 두 번" 시험이 다시 열기 코드를 실제로 타는지 불확실(브라우저가 두 번째 Esc도 막으면 onClose가 안 불림) — R3. 확인: 그 줄을 지우고도 통과하는지. 고치는 방법: `dialog.close()`를 직접 불러 강제로 닫고 다시 열리는지 확인.
