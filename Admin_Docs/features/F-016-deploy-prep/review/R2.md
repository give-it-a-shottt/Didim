## 지적
- [신규] [제안] [확실] 처리 안 된 예외로 나는 500 응답에는 nosniff가 없다 — Starlette는 ServerErrorMiddleware → 사용자 미들웨어 → ExceptionMiddleware 순으로 감싸고 500은 가장 바깥이 만든다. 본문이 평문 한 줄이라 영향은 거의 없음. — main.py 43–63행, security_headers.py — 고치는 방법: D-032에 '500은 예외' 한 줄(반영함), 또는 Exception 핸들러에서 직접.
- [신규] [제안] [확실] 체크리스트의 PowerShell 5.1 명령이 환경변수만 지우고 `$s`(SecureString)는 세션에 남김 — `Remove-Variable s` 또는 '창 닫기'(반영함).

## 체크 항목별 근거
- 에러 응답 머리말 → SecurityHeaders가 마지막 add_middleware라 가드 401 · 403과 404에도 붙음(테스트) → 적절(500만 예외).
- 개인 응답 캐시 → 요청에 세션 쿠키가 있으면 no-store, 응답이 정한 값은 존중, 부분 문자열 일치는 안전한 쪽, HTTP/2 여러 cookie 줄도 봄, 로그인 콜백은 범위 밖(D-032에 근거) → 적절.
- 운영 설정 실패 시 닫힘 → import 때 검사, 운영 /docs · /openapi.json · /redoc 404와 목록 없는 import 실패를 하위 프로세스로 확인 → 적절.
- 민감 정보 → vercel.json · 체크리스트 · 테스트에 비밀값 없음, Production · Sensitive 안내 → 적절.
- 패키지 → 추가 없음(starlette.types는 기존 의존성).
- 연결 · 지역 → NullPool + 같은 지역(icn1 ↔ ap-northeast-2), 실제 수치는 배포 뒤 /home 응답 시간 → 적절.
- 함수 시간 → 150초 상한, AI 100초, 노션 80초 → 어긋나지 않음.

확인한 범위: 패킷 전체, main.py 43–64행, config.py SESSION_COOKIE_NAME. 실행 · 배포 확인과 .env 열람은 안 함.
