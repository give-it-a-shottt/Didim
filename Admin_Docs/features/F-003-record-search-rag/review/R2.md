## 체크 항목별 근거
- 보안·프론트 XSS · 토큰 저장 · 공개 환경변수 · 화면 접근 차단 → diff.patch → 해당 없음. 프론트는 바뀌지 않았다(패킷 "프론트는 바뀌지 않아").
- 보안·백엔드 인증과 권한(남의 데이터 접근 차단, D-004) → keyword.py `_build_statement` → 문제 없음 [확실]. 후보 CTE의 `Chunk.user_id == user_id`(50행), 결과 단계의 `Note.user_id == user_id` 조인(91행)과 `Chunk.user_id == user_id`(92행)가 그대로 남아 있다. 새 `scored` · `ranked`는 이미 사용자로 걸러진 candidates만 읽는다. 노트로 나누는 PARTITION도 그 안에서만 일어나 다른 사용자의 행이 섞일 경로가 없다.
- 보안·백엔드 입력 검증 → search_service.py · evaluation.py diff → 문제 없음 [확실]. `max_per_note`는 사용자 입력이 아니고 config 상수 `MAX_SEARCH_RESULTS_PER_NOTE = 2`만 넘어온다. `q` · `limit` 검증은 이번에 바뀌지 않았다(api-list 발췌 기준).
- 보안·백엔드 SQL 인젝션 → keyword.py → 문제 없음 [확실]. `max_per_note`는 SQLAlchemy 비교식(`note_rank <= max_per_note`)이라 바인드 파라미터로 들어가고, 문자열을 이어 붙이는 SQL은 없다. 낱말은 예전처럼 `literal(term, Text)`로 넘어간다.
- 보안·백엔드 CORS · 비밀키 하드코딩 → diff.patch → 해당 없음. 바뀌지 않았고, 새 상수는 비밀값이 아니다.
- 보안·백엔드 에러 응답에 내부 정보 노출 → keyword.py `run_with_search_settings` → 바뀌지 않음. 시간 초과는 예전처럼 SearchTimeoutError(고정 문구)로 바뀐다.
- 보안·공통 패키지 취약점 → diff.patch → 해당 없음. 패키지는 바뀌지 않았다.
- 보안·공통 Admin_Docs · 코드의 민감 정보 → diff.patch와 `git diff Admin_Docs`(STATUS · feature.md · api-list, 각 1줄) → 민감 정보 없음 [확실].
- 성능·프론트 리렌더링 · 번들 · 이미지 · API 호출 → 해당 없음. 프론트가 바뀌지 않았다.
- 성능·백엔드 N+1 쿼리 → keyword.py → 문제 없음 [확실]. 검색 한 번이 여전히 SQL 한 문장(CTE → scored → ranked → 본문 조인)이고, 노트별 거르기를 파이썬 반복이나 추가 쿼리로 하지 않는다.

- 성능·백엔드 무거운 작업의 동기 처리 · 시간 상한 → keyword.py `run_with_search_settings` → 문제 없음 [확실]. statement_timeout(3초)은 문장 전체에 걸리므로 새 WindowAgg · Sort도 같은 3초 안에서 멈춘다. 늘어난 정렬 비용이 상한을 우회하는 경로는 없다. 실제 여유 시간은 [추정](위 [제안]).
