## 지적
- [신규] [제안] [추정] 처리 중 Esc를 막아도, Chromium 계열은 같은 `cancel`을 사용자 조작 없이 연달아 막으면 두 번째에는 `dialog`를 강제로 닫을 수 있다. 그러면 `onClose`가 `close()`를 불러 `ImportFlow`가 사라지고, 요청은 계속 진행돼 저장은 되지만 결과 화면을 못 보고, `onSaved`가 닫힌 뒤에 불려 `router.refresh()`도 일어나지 않는다. — 위치: frontend/src/components/import-records-dialog.tsx:78-84 · 59-63 · 95-97 — 확인한 범위: dialog.tsx 코드 읽기(브라우저에서 실행하지 않음) — [확실]이 되려면: Playwright에서 `/api/notes/import`를 몇 초 지연시키고 처리 중에 Esc를 두 번 눌러 다이얼로그가 닫히는지 확인한다. — 고치는 방법: 닫히는 경우 `onClose`에서 `isBusy`면 `dialog.showModal()`로 다시 열거나, 닫혀도 `onSaved`/refresh가 살아 있게 `savedRef` 처리를 `ImportFlow` 밖(요청이 끝나는 곳)으로 옮긴다.
- [신규] [제안] [확실] 새로 생긴 화면 동작을 확인하는 Playwright가 없다. (a) 처리 중 Esc를 눌러도 모달이 유지되는지, (b) 결과를 본 뒤 닫았다가 다시 열면 올리기 단계로 돌아가고 이전 파일 선택이 지워지는지(`key`로 새로 그리기). 둘 다 이번 리팩터링의 핵심 동작인데 시험이 없어 이후 수정에서 조용히 깨질 수 있다. — 위치: frontend/tests/import-records.spec.ts(전체), 동작은 import-records-dialog.tsx:42-103 — 확인한 범위: spec 파일 전체, dialog.tsx — 고치는 방법: 지연시킨 `page.route`로 처리 중 `page.keyboard.press("Escape")` 후 `IMP_01_002`가 보이는지, 결과 후 확인 → 다시 "+ 기록 추가"를 눌러 `IMP_01_001`이고 가져오기 버튼이 비활성인지 확인하는 테스트 두 개를 더한다.
