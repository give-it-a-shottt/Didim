# D-013 프론트엔드 테스트 도구는 Playwright로 한다

## 한눈에 보기 (코드 몰라도 OK)
상태: [통과] 사용자가 골랐어요(2026-11-09).
무엇을: 화면이 실제로 잘 열리고, 로그인하지 않았을 때 회원 화면이 `/login`으로 보내지는지를 실제 브라우저(Playwright)를 띄워서 자동으로 검사해요.
왜 (사용자 확인): 브라우저와 서버를 실제로 띄워서 19개 URL이 잘 열리는지(스모크 테스트)와 로그인하지 않았을 때 `/login`으로 이동하는지를 한 번에 확인하기 위해 Playwright를 골랐다.

## 개발자 상세

### 상황
- [F-013](../features/F-013-screen-skeleton/feature.md) 리뷰에서 19개 URL과 리다이렉트를 손으로 확인했는데, 앞으로 기능을 붙일 때마다 깨지지 않았는지 자동으로 다시 돌릴 테스트가 필요했다(Q-014).
- [F-001](../features/F-001-account-isolation/feature.md)에서는 비로그인 상태로 회원 화면에 접근했을 때 `/login`으로 이동하는지도 함께 검증해야 한다.

### 후보
| | A. Playwright (E2E · 스모크 테스트) | B. Vitest + Testing Library (단위 · 컴포넌트) |
|---|---|---|
| 확인 범위 | Next.js 서버를 실제로 띄워 라우팅, 리다이렉트(307), 쿠키 기반 로그인 보호, 메타데이터를 브라우저 수준에서 확인 | 개별 컴포넌트 렌더링과 함수 단위 동작을 빠르게 확인 |
| 장점 | App Router 서버 컴포넌트 · 레이아웃 리다이렉트 · 쿠키 흐름을 실제와 똑같이 검증 | 실행 속도가 빠르고 가벼움 |
| 단점 | 서버 구동 시간이 걸림 | Next.js App Router의 라우팅 · 서버 리다이렉트 전체 흐름을 그대로 검증하기 어려움 |

### 결정
- A. Playwright로 URL 스모크 테스트와 인증 리다이렉트 테스트를 작성한다.

### 결과로 생기는 제약
- 프론트 테스트를 돌릴 때 Next.js 서버가 함께 떠야 한다(`playwright.config.ts`의 `webServer` 설정 사용).

### 이 결정을 바꿔야 하는 조건
- 화면 안의 복잡한 계산 함수나 순수 UI 상태 로직이 많아져 브라우저를 띄우지 않는 빠른 단위 테스트가 별도로 필요해질 때 → 그 부분에만 Vitest를 추가한다.
