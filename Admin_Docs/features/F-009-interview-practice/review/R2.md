## 지적 (있을 때)
- [신규] [제안] [확실] 선점한 뒤 return 전에 DB 오류가 나면 선점이 5분 동안 남는다. 2차 반영으로 `claim_target` 다음에 `_has_questions` 다시 확인과 `db.rollback()`이 들어왔는데, 이 둘 중 하나가 예상 못 한 오류(DB 연결 끊김 등)를 내면 라우터는 `_PREPARE_ERRORS`에 없는 예외라 그냥 500을 내고, `card_interview_claims` 줄은 지워지지 않는다. D-020(사용자당 AI 작업 1개) 때문에 그 사용자는 5분 동안 모든 AI 기능에서 409를 받는다. 실제로 일어날 가능성은 낮고 5분 뒤 저절로 풀린다 — 위치: `backend/app/services/interview_service.py` `prepare_interview`(146~151줄), `backend/app/api/interview.py` `write_interview_endpoint`(116~119줄) — 확인한 범위: 패킷의 두 파일 전체, `note_claim.claim_target` 앞부분(직접 열람) — 고치는 방법: 선점 뒤 부분을 `try: ... except QuestionsAlreadyExist: raise / except Exception: db.rollback(); release_claim(...); raise`로 감싸 선점을 풀고 올린다(테스트: 두 번째 `_has_questions`가 오류를 내면 선점이 남지 않는지).
- [신규] [제안] [확실] 이번 2차 반영(AI 기다리기 전 `db.rollback()`, 선점 뒤 다시 확인, 선점을 잃은 저장)은 트랜잭션 · 잠금 동작이라 PostgreSQL에서 확인해야 의미가 있는데 이번엔 SQLite로만 돌렸다(패킷: Docker 꺼짐). SQLite는 `with_for_update`를 무시하고 'idle in transaction'도 재현되지 않는다 — 위치: `backend/tests/test_interview.py` `test_prepare_closes_its_transaction_before_the_ai_call` · `test_saving_after_losing_the_claim_saves_nothing` · `test_questions_saved_between_check_and_claim_stop_before_ai` — 확인한 범위: 패킷의 테스트 결과 · 테스트 이름 목록 — 고치는 방법: 커밋 전에 PostgreSQL로 `uv run pytest -q tests/test_interview.py`를 한 번 돌려 결과를 STATUS에 남긴다(코드 수정 아님).
