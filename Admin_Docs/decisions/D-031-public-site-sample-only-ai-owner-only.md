# D-031 공개 배포에서는 샘플 체험 · 평가 리포트만 열고, AI를 부르는 회원 기능은 허용한 이메일(본인)만 쓴다

## 한눈에 보기 (코드 몰라도 OK)
상태: [통과] 사용자가 골랐어요(2026-11-19). 허용 목록 기능은 F-015로 만들어요(설계 의도 확인 후).
무엇을: 배포한 사이트에서 누구나 볼 수 있는 건 랜딩 · 평가 리포트(`/report`) · 샘플 체험(`/demo`, 읽기 전용 — AI를 부르지 않음)이에요. 구글 로그인은 서버가 허용 목록의 이메일(본인)만 받고, 그 밖의 계정은 '지금은 샘플 체험만 열려 있어요' 안내로 보내요. 그래서 AI를 부르는 기능(퀴즈 · 카드 · 공고 분석 · 자소서 · 면접 질문)은 본인만 써요.
왜 (사용자 선택): 메인 AI인 NVIDIA 무료 API는 체험판이라 입력과 출력이 기록되고 모델 개선에 쓰일 수 있어요(D-027). 본인 기록만 보낼 때는 괜찮지만, 다른 사람이 가입하면 그 사람의 공부 기록과 경험이 그대로 넘어가요 — "타인 개인정보는 보내지 않는다"(설계 원칙 6)와 부딪혀요. 한도(분당 40번)도 계정 하나를 모두가 나눠 쓰게 돼요. 그래서 면접관에게는 같은 기능을 샘플 체험과 평가 수치로 보여 주고, 실제 AI 동작은 본인 시연으로 보여 줘요.

## 개발자 상세

### 후보
| 후보 | 장점 | 단점 |
|---|---|---|
| A. 누구나 가입해 AI 사용 | 면접관이 바로 써 봄 | 타인 기록이 체험판 API에 기록됨(원칙 6), 한도 공유, 체험판 약관 위험 |
| B. 허용한 이메일(본인 + 초대한 면접관)만 AI | 면접관도 직접 써 봄 | 초대 · 안내가 필요, 초대받은 사람의 기록도 체험판 API로 감 |
| C. 공개는 샘플 · 리포트만, AI는 본인만 (선택) | 타인 기록을 보내지 않음, 한도를 혼자 씀 | 면접관은 AI를 직접 못 써 봄 — 샘플(실제 AI 결과를 다시 들려준 데이터) · 리포트 수치 · 시연으로 대신 |

### 막는 방법 (사용자 선택 2026-11-19)
| 방법 | 장점 | 단점 |
|---|---|---|
| 서버가 허용 이메일만 로그인 (선택) | 서비스 쪽에서 확실히 막힘, 막힌 사람에게 우리 말로 안내 | 코드가 조금 필요(F-015) |
| 구글 OAuth 앱을 '테스트' 상태로 | 코드 없음 | 구글 오류 화면만 보임, 콘솔 설정을 바꾸면 바로 열림(서비스 쪽 장치 없음) |
| 운영에서 로그인 숨기기 | 가장 단순 | 본인도 배포 사이트에서 AI를 못 씀, 랜딩 문구 변경 |

### 결정
- 공개 범위: 랜딩 · `/report` · `/demo`(샘플 세션 — 쓰기 · AI 호출은 서버가 막음, D-029)는 누구나. 회원 화면과 AI 기능은 허용한 이메일로 로그인한 사람만.
- 허용 목록은 환경변수로 두고 서버가 확인한다. 세부(변수 이름 · 확인 시점 · 막힌 사람에게 보일 안내 · 비어 있을 때 동작)는 F-015 설계 의도에서 정한다.
- 덧붙임(사용자 선택 2026-11-19, F-015 1 · 2차 리뷰): 운영(`COOKIE_SECURE=true`, 또는 `FRONTEND_URL` · `GOOGLE_REDIRECT_URI` 중 하나라도 https · localhost가 아님)에서 목록이 비면 서버가 시작하지 않는다(운영인데 `COOKIE_SECURE`가 꺼져 있으면 경고만 — Secure 강제 여부는 Q-012에서) — 빠뜨린 채 조용히 열리지 않게. ASCII가 아닌 이메일은 받지 않는다(유니코드를 소문자로 바꾸면 다른 주소가 같아질 수 있어서). 허용 기준은 구글 계정 번호(sub)가 아니라 이메일로 두고, 운영 목록에는 Gmail 주소를 쓴다(회사 · 학교 주소는 나중에 다른 사람에게 넘어갈 수 있어서). 다른 방법 — 목록이 비면 막고 `*`로 열기, sub로 고정 — 은 고르지 않았다.
- 이 결정으로 Q-019(EXAONE을 공개 서비스에서 써도 되나)는 '공개 서비스에서 남이 AI를 부르지 않음'으로 닫는다. Q-012의 '면접관 시연 방식'은 샘플 체험 + 평가 리포트 + 본인 시연(필요하면 영상)으로 정한다.
- README에 '공개 범위 — 왜 AI 기능은 샘플로 보여 주나'를 남긴다(포트폴리오에도 옮겨 쓸 설명).

### 이 결정을 바꿔야 하는 조건
- 데이터를 기록하지 않는 유료 AI(또는 자체 서버 모델)로 바꾸면 A나 B를 다시 본다 — 그때는 비용 상한(원칙 4)과 개인정보 안내(원칙 6)를 같이 정한다.
- 면접관이 직접 써 보는 것이 꼭 필요하면 B(초대한 이메일 추가)로 넓힌다 — 허용 목록에 이메일을 더하는 것만으로 되게 F-015를 만든다.
