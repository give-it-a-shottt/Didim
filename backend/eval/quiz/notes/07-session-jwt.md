# 세션과 JWT

## 세션 방식
세션 방식에서는 로그인하면 서버가 세션 ID를 만들어 서버 쪽 저장소(메모리, Redis, DB)에 사용자 정보와 함께 저장하고, 브라우저에는 세션 ID만 쿠키로 준다. 요청마다 서버가 저장소에서 세션 ID를 찾아 누구인지 확인한다.

## JWT 방식
JWT는 사용자 정보와 만료 시각을 토큰 안에 담고 서버의 비밀 키로 서명한 것이다. 서버는 저장소를 찾지 않고 서명만 검증하면 되므로 서버를 여러 대로 늘리기 쉽다. 다만 토큰 내용은 서명만 됐을 뿐 암호화되지 않아서 누구나 디코딩해 읽을 수 있으므로 비밀번호 같은 값은 넣지 않는다.

## 로그아웃 문제
JWT는 서버가 따로 저장하지 않기 때문에, 한 번 발급하면 만료 시각 전까지는 서버가 무효로 만들기 어렵다. 그래서 액세스 토큰의 유효 시간을 15분 정도로 짧게 두고, 더 오래 가는 리프레시 토큰으로 새 액세스 토큰을 발급받는 구조를 많이 쓴다.

## httpOnly 쿠키
토큰을 localStorage에 두면 페이지에 주입된 스크립트(XSS)가 읽어 갈 수 있다. 쿠키에 `HttpOnly` 속성을 주면 자바스크립트의 `document.cookie`로 읽을 수 없어서 XSS로 토큰을 훔쳐 가는 것을 막을 수 있다.

## SameSite
쿠키의 `SameSite=Lax`는 다른 사이트에서 시작한 POST 요청에는 쿠키를 붙이지 않고, 다른 사이트의 링크를 눌러 들어오는 GET 이동에는 붙인다. 그래서 대부분의 CSRF 공격을 막으면서도 외부 링크로 들어왔을 때 로그인이 풀리지 않는다.
