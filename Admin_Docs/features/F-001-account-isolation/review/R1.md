## 체크 항목별 근거 (항상 작성, 항목당 한 줄)
- 프론트 구조 → `frontend/src/lib/auth.ts`, `frontend/src/components/member-auth-guard.tsx`, `frontend/src/components/logout-button.tsx`, `frontend/src/app/(app)/layout.tsx`, `frontend/src/app/(focus)/layout.tsx`, `frontend/src/app/(guest)/login/page.tsx`, `frontend/src/app/(app)/settings/page.tsx` → `architecture.md`의 폴더 구조와 일치하며, 각 컴포넌트가 단일 책임을 갖고 D-012 상태 관리 지도대로 사용자 정보는 서버 컴포넌트(`requireCurrentUser`)에, 로그아웃 진행·오류 상태는 `LogoutButton` 로컬 `useState`에 적절히 배치됨.
- 백엔드 구조 → `backend/app/main.py`, `backend/app/api/auth.py`, `backend/app/api/deps.py`, `backend/app/services/auth_service.py`, `backend/app/services/note_service.py`, `backend/app/db/session.py` → 라우터(`api`)는 HTTP 요청·응답·쿠키 처리만 담당하고 OAuth 교환·토큰 서명·DB 조회 비즈니스 로직은 모두 `services` 계층에 위임하여 `api → services → db` 단방향 의존이 지켜짐.
- 데이터 → `backend/app/db/models.py`, `backend/app/db/session.py` → `data-model.md`의 1주차 스키마(`users`, `notes`, `chunks`)와 컬럼·타입·제약(`google_sub` UNIQUE, `(user_id, content_hash)` 복합 UNIQUE, `user_id`·`note_id` `ON DELETE CASCADE`, `NOT NULL`)이 일치하며 SQLite 연결 시 `PRAGMA foreign_keys=ON`도 활성화됨.
- 가독성 → `backend/app/config.py`, `backend/app/services/auth_service.py`, `backend/app/services/note_service.py`, `frontend/src/lib/auth.ts` → 쿠키 만료 시간·최소 비밀키 길이·일일 상한 등 매직 넘버가 상수로 분리되어 있고, `*_for_user` 등 함수명이 D-004 격리 의도를 명확히 드러내며 죽은 코드나 불필요한 중복이 없음.
