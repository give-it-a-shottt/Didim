# T-006 EXAONE 무료 API로 평가를 돌리면 500 · 429 · 하루 한도 · 180초 상한에 걸림

## 한눈에 보기 (코드 몰라도 OK)
상태: [통과] 우회 방법을 정했어요(2026-11-12). 무료 API의 한도라서 없앨 수는 없어요.
무슨 문제였나: 평가는 노트 10~18개에 AI를 연달아 부르는데, 무료 EXAONE이 ① 서버 오류(500) ② "너무 자주 불렀어요"(429) ③ 그날 한도를 다 쓰면 모든 호출을 429로 막고 ④ 느린 시간대에는 180초 안에 답을 못 줬어요. 그래서 평가가 일부 또는 전부 실패했어요.
어떻게 해결했나: 평가 스크립트가 호출 사이에 쉬고, 500 · 429면 기다렸다 다시 해요. 결과는 노트마다 바로 저장해서 중간에 멈춰도 남아요. 하루 한도에 걸리면 다음 날 다시 재고, 실패한 노트는 다른 회차에서 성공한 결과와 합쳐 판정해요(사용자 확인).

## 개발자 상세

### 1. 500 · 429 — 짧은 간격의 연속 호출
- 증상: F-004 퀴즈 평가(2026-11-11)에서 EXAONE HTTP 500 7번 · 429 대기 9번. F-006 카드 평가 1차(같은 날 오후)에서 18개 중 4개가 429로 실패.
- 원인(추정): 무료 API가 짧은 간격의 연속 호출을 막는 것으로 보임. 한도 값은 공개 문서에서 확인하지 못함.
- 해결: `scripts/quiz_eval.py` · `scripts/card_eval.py`에 `--pause`(호출 사이 최소 간격, 기본 20초), `--retries`(500 · 429면 노트마다 다시, 기본 2번), `--retry-wait`(다시 하기 전 쉬는 시간, 기본 60초). 카드 평가는 `--pause 40`으로 돌림.

### 2. 하루 한도 — 그날 남은 호출이 모두 429
- 증상: 카드 평가 저녁 재측정(2026-11-11, `--pause 40`)에서 18개 노트 모두 429, 호출 216번 거절.
- 원인(추정): 하루 사용 한도. 다음 날 아침 같은 명령은 429 대기 18번이 있었지만 대부분 통과함.
- 해결: 평가 결과를 노트마다 저장(`complete` 표시)해 중간 결과를 잃지 않게 함. 한도에 걸리면 그날은 멈추고 다음 날 다시 잰다. 실패만 모인 결과 파일은 지운다.

### 3. 느린 시간대 — 전체 180초 상한 초과
- 증상: 카드 평가 2차(2026-11-12 아침)에서 경험 노트 5개가 `LLM 호출 실패(timeout), 시도 1/2` → `LLM 전체 시간 상한(180초) 초과, 스키마 CardBatchIn` → `LLMUnavailable`. 성공한 노트도 중앙값 54초 · 최대 126초.
- 원인: EXAONE은 항상 추론한 뒤 답한다(D-014, `reasoning_effort`는 이미 가장 가벼운 `low`). 응답이 느린 시간대에는 재시도까지 합쳐 180초(F-014 전체 상한)를 넘긴다.
- 해결: 상한은 그대로 둠(사용자 화면이 3분 넘게 멈추지 않게). 평가 판정은 노트마다 성공한 회차를 합쳐 본다 — F-006 1차(경험 노트 8개 모두 성공) + 2차(경험 없는 노트 10개 모두 성공)(사용자 확인 2026-11-12).
- 실제 화면 영향: 같은 시간대에 [카드 후보 찾기]를 누르면 "다시 시도해 주세요" 오류가 날 수 있다. 선점이 풀려 다시 누를 수 있다.

### 재발 방지
- 평가는 하루 한 번, 오전에 돌린다. 같은 날 여러 번 재지 않는다.
- 평가 실행 중에는 화면에서 AI 버튼을 누르지 않는다(같은 키 · 같은 한도).
- 공개 배포 계획이 없어 모델은 그대로 쓴다(Q-019 닫음, D-014). 바꿀 때는 `LLM_PROVIDER`만 바꾸면 된다.
