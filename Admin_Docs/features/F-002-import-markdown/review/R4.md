## 지적
- [제안] [확실] D-001은 "가져오기 어댑터 인터페이스(MarkdownAdapter, NotionAdapter)"를 말하는데, 지금은 공통 모양(ImportedDocument)과 함수 read_markdown_file만 있고 인터페이스(Protocol 등)가 없다. import_service가 마크다운 함수를 직접 부른다. 4주차 노션을 붙일 때 서비스 코드를 고쳐야 한다. — 위치: backend/app/services/import_service.py:16 · 87, backend/app/importers/base.py:1-19 — 확인한 범위: D-001 본문, importers/base.py · markdown.py, import_service.py 전체 — 고치는 방법: base.py에 `read(...) -> ImportedDocument`를 가진 Protocol을 두고 서비스는 그 타입을 받게 하거나, "1주차는 공통 모양만 두고 인터페이스는 4주차에 노션과 함께 만든다"를 architecture.md에 한 줄 적는다(둘 중 사용자가 고름).
- [제안] [확실] 본문이 하나도 없고 제목만 있는 파일(예: `# React` 한 줄)은 조각이 0개인데 노트는 저장되고 "노트 1 · 조각 0"으로 성공 처리된다. 완료 기준 1은 "노트 1개 + 조각 여러 개"이고, 조각이 없는 노트는 이후 퀴즈 · 카드의 근거 재료가 못 된다. 이 경우를 성공으로 둘지 실패("읽을 내용이 없어요")로 둘지는 설계 의도에 없고 테스트에도 없다(제목만 있는 구역 테스트는 test_import_markdown.py:96의 다른 구역 사례). — 위치: backend/app/services/chunking.py:123-124, backend/app/services/import_service.py:102-111 — 확인한 범위: chunking.py 전체, import_service.py 전체, test_import_markdown.py에서 관련 단어 검색 — 고치는 방법: 사용자에게 한 줄로 물어 정한다(현재 동작 유지 / 조각 0개면 실패 처리). 정해지면 테스트 한 줄과 feature.md에 반영. 큰 영향이 없으면 OPEN_QUESTIONS 대신 보고 항목으로 충분.
