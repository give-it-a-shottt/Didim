## 지적
1. [주의] [확실] `create_note_for_user`가 던지는 `ChunkLocationError`를 호출부가 잡지 않는다. `_import_one`은 `DuplicateNoteError`와 `SQLAlchemyError`만 잡으므로(ChunkLocationError는 ValueError), 나누기 쪽에 버그가 있어 위치 검사에 걸리면 요청 전체가 500이 되고, 이미 commit된 앞 파일의 결과 목록도 사용자에게 가지 않는다(다시 올리면 전부 '중복'으로 보임). 완료 기준 4(일부 실패해도 성공 파일 유지·실패 이유 표시)와 어긋난다. 걸리는 경우는 버그뿐이라 발생 가능성은 낮다. — 위치: backend/app/services/import_service.py:104-136 — 확인한 범위: import_service.py, note_service.py의 예외 정의·검사 위치(diff) — 고치는 방법: `except ChunkLocationError`를 추가해 `logger.exception`(user_id만) 뒤 그 파일만 failed(SAVE_FAILED_REASON)로 돌리고, 그 경로를 부르는 API 수준 테스트를 하나 둔다(split_markdown을 어긋난 조각을 내는 것으로 바꿔 끼움).
2. [주의] [확실] 프론트 `submit`에 예외 처리가 없다. `importMarkdownFiles`는 200 응답의 `await response.json()`을 try 없이 호출하므로(import-records.ts:66), 200인데 본문이 JSON이 아니면(프록시 오류 화면 등) 예외가 올라와 `submit`이 끝나지 않고 단계가 "processing"에 남는다. 처리 중에는 닫기 버튼이 없고 Esc도 막혀(import-records-dialog.tsx:103-105) 모달을 닫을 수 없다. 발생 가능성은 낮다. — 위치: frontend/src/lib/import-records.ts:65-67, frontend/src/components/import-records-dialog.tsx:70-85 — 확인한 범위: 두 파일 diff 전체 — 고치는 방법: 200 분기의 `response.json()`을 try/catch로 감싸 실패하면 `{ ok:false, message: FALLBACK_ERROR }`를 돌려주거나, `submit`을 try/catch로 감싸 error 단계로 보낸다.
3. [주의] [확실] 파일마다 저장하는 구조의 핵심 보장(저장 실패 → 그 파일만 failed, 앞 파일 유지, 세션 계속 사용)과 중복 경쟁 경로를 확인하는 테스트가 없다. `test_partial_failure_keeps_successful_files`는 읽기 실패(확장자·용량·인코딩)만 다룬다. `except SQLAlchemyError`(import_service.py:125-130), `except DuplicateNoteError` 안의 `existing is None` 분기(116-118)는 어떤 테스트도 지나가지 않는다. — 위치: backend/tests/test_import_markdown.py(232-251) — 확인한 범위: 테스트 파일 전체와 import_service.py — 고치는 방법: 두 번째 파일에서 `create_note_for_user`가 `OperationalError`를 던지도록 바꿔 끼우고(monkeypatch) 응답이 200이며 첫 파일은 저장·둘째는 failed·셋째는 정상 저장인지 확인한다. 중복 경쟁은 첫 `find_note_by_content_hash_for_user` 호출만 None을 돌리게 바꿔 duplicates로 분류되는지 확인한다.

[제안] [확실] 나누기·읽기 경계 테스트가 부족하다. 없는 것: (a) 제목 한 줄만 있는 파일(조각 0개, 노트만 저장되는 결과가 의도인지 확인), (b) 닫히지 않은 코드 블록, (c) 4칸 들여쓴 코드 블록 안 `#`, (d) 맨 앞에 제목 없는 글만 있는 구역과 제목 단계가 건너뛰는 경우(# → ###), (e) 기준 길이 경계 정확히 1,500자. 지금 코드는 읽기상 맞게 동작하는 것으로 보이나 고정해 둔 테스트가 없다. — 위치: backend/tests/test_import_markdown.py(93-145) — 확인한 범위: chunking.py, markdown.py, 테스트 파일 — 고치는 방법: 위 사례마다 `split_markdown`에 넣고 `_assert_chunks_are_slices`와 조각 개수·경로를 확인하는 작은 테스트를 추가한다. (a)는 노트가 조각 0개로 저장되어도 되는지 사용자 확인이 필요할 수 있다.
6. [제안] [추정] `db.refresh(note)`가 commit 뒤 try 밖에서 불리는데 `create_note_for_user` 자체가 호출부의 `except SQLAlchemyError` 안에 있다. refresh가 실패하면 노트는 이미 저장됐는데 화면에는 failed로 나오고, 다시 올리면 '중복'이 된다. 확인하면 [확실]이 되는 것: refresh 실패를 일으켜 보고 결과 목록과 DB 상태를 비교. 지금 DB 연결이 commit 직후 끊기는 드문 경우뿐이다. — 위치: backend/app/services/note_service.py:76, import_service.py:104-130 — 확인한 범위: diff와 note_service 해당 부분 — 고치는 방법: refresh를 없애고(id는 commit 뒤 note.id로 읽을 수 있음, expire_on_commit 설정 확인) 응답에 필요한 값은 commit 전에 변수로 보관한다.
