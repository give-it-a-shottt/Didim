- [주의] [확실] 검색 로그 저장이 실패해도 결과는 돌려주는 동작(롤백 + 경고 로그 + 정상 응답)이 코드에는 있는데 테스트가 없다. 이 분기가 깨져도(예: rollback 빠짐, 예외 종류가 안 잡힘) 테스트가 모두 통과한다. D-005 로그가 평가의 근거라 "조용히 실패"하는 경로는 확인해 둘 가치가 있다 — backend/app/services/search_service.py:50-67(`_save_log`) · backend/tests/test_search.py(해당 테스트 없음) — 확인한 범위: search_service.py 전체 + test_search.py 전체 + 패킷의 테스트 결과 — 고치는 방법: FakeSearcher(DB 종류 무관)로 `db_session.commit`을 SQLAlchemyError로 바꿔 끼운 테스트 1개를 추가해 "200 + 결과 그대로 + search_logs 0건"을 확인한다. 검색어에 NUL(\x00) 같은 DB가 거부하는 글자를 넣은 경우도 같은 경로를 탄다.

- [주의] [확실] 화면의 실패 분기(백엔드 연결 실패 · 500 · 응답 모양 틀림 → `status: "error"`)가 Playwright에서 한 번도 실행되지 않는다. 모의 서버가 503(검색불가)만 흉내 낸다. 노트 상세의 "노트를 불러오지 못했어요" 분기도 같다. 코드는 에러 상태를 처리하지만 실제로 보이는지 확인된 적이 없다 — frontend/src/lib/records.ts:55-125 · frontend/src/app/(app)/records/page.tsx:72-82 · frontend/src/app/(app)/records/[noteId]/page.tsx:32-43 · frontend/tests/mock-backend.mjs · frontend/tests/record-search.spec.ts — 확인한 범위: 위 파일 전체 diff — 고치는 방법: 모의 서버에 "검색오류"(500)와 노트 번호 하나(예: 500)를 500으로 답하게 추가하고, 각각 "검색하지 못했어요" · "노트를 불러오지 못했어요" 문구를 확인하는 테스트를 넣는다.

- [제안] [추정] 세션이 만료된 쿠키(백엔드 401)가 오면 검색은 "검색하지 못했어요"로, 노트 상세는 "노트를 불러오지 못했어요"로 표시되고 로그인 안내는 없다. `fetchAsUser`가 401을 구분하지 않고 `response.ok`가 아니면 모두 error로 합친다 — frontend/src/lib/records.ts:107-113, 144-150. 쿠키는 있으나 서명이 만료된 상태에서 (app) 레이아웃이 통과시키는지 확인하면 [확실]이 된다(레이아웃 코드는 이번 diff에 없어 열지 않음). 고치는 방법: 401이면 로그인 화면으로 보내거나 `unauthorized` 상태를 따로 두어 "다시 로그인해 주세요"를 보여 준다.

- [제안] [추정] 검색 쿼리 자체가 DB 오류를 내는 경우(예: 배포 DB에 pg_trgm이 없음, 연결 끊김)는 `SearchUnavailableError`가 아니라 SQLAlchemy 예외로 올라가 500이 된다. 503은 "SQLite일 때"만 쓰인다. 화면은 500도 "검색하지 못했어요"로 처리하므로 사용자에게는 문제가 없지만 서버 로그에 원인 구분이 없다. Q-012 임시 처리(0003의 확장 설치 권한)와 관련 — backend/app/search/keyword.py:38-39, backend/app/api/search.py:55-58. 고치는 방법: 확장이 없을 때의 응답을 정할 때(Q-012 배포 시) 함께 정한다. 지금은 조치 불필요.

- [제안] [확실] 입력 검사 테스트가 `limit`의 위쪽 경계(6 → 422)만 보고 아래쪽(0 → 422)과 숫자가 아닌 `chunk`/`noteId` 주소(`/records/abc` → 404, `?chunk=abc` → 강조 없이 원문) 화면 경로는 보지 않는다. 코드는 처리한다(`ge=1`, `DIGITS_ONLY`, `sliceByCodePoints`가 범위 밖이면 null) — backend/tests/test_search.py:98-102, frontend/tests/record-search.spec.ts. 고치는 방법: 기존 테스트에 `limit=0` 한 줄, Playwright에 `/records/abc` · `/records/1?chunk=999` 한 번씩 추가(비용이 작음). `sliceByCodePoints`는 순수 함수라 범위 밖 · 이모지 단위 테스트를 따로 둘 수도 있다.
