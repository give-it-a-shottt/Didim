# D-001 기록 가져오기는 마크다운 먼저, 노션은 4주차

## 한눈에 보기 (코드 몰라도 OK)
상태: [통과] 사용자가 골랐어요(2026-11-05).
무엇을: 1주차에는 마크다운 파일을 올리는 방식만 만들고, 노션 연결은 4주차에 붙여요. 가져오는 부분은 "어댑터"로 만들어서, 어디서 가져오든 같은 모양의 기록으로 바꿔 넣어요. 콘센트 모양이 달라도 변환 플러그만 바꾸면 같은 전기를 쓰는 것과 같아요.
왜: 노션 연결은 로그인 · 권한 설정이 많아서 처음부터 하면 뼈대가 늦어져요. 노션 페이지는 마크다운으로 내보낼 수 있어서 처음 쓰는 사람도 쓸 수 있어요.

## 개발자 상세

### 후보
| 후보 | 장점 | 단점 |
|---|---|---|
| A. 마크다운 먼저 → 노션 4주차 (선택) | 1주차에 업로드 → 검색 뼈대를 바로 확인 | 노션 사용자는 4주차까지 내보내기를 거쳐야 함 |
| B. 노션 연결부터 | 실제 사용 흐름과 같음 | OAuth · 토큰 관리로 1~2주가 밀림 |
| C. PDF까지 지원 | 범위가 넓음 | 문서 파싱이 별도 작업이라 8주 MVP에서 제외 |

### 결정
- A. 가져오기 어댑터 인터페이스(`MarkdownAdapter`, `NotionAdapter`)가 같은 기록 모양을 돌려준다.
- PDF는 MVP에서 뺀다. 깃허브 기록 가져오기는 어댑터 자리만 열어 두고 2차.

### 결과로 생기는 제약
- 노션 토큰이 만료되거나 권한이 회수되면 "노션 연결이 끊겼어요" → 설정에서 재연결(예외 1).
- 같은 노트를 다시 올리면 중복 안내(예외 5).

### 이 결정을 바꿔야 하는 조건
- 4주차 노션 연결이 밀리면 마크다운만으로 MVP를 낸다(랜딩 축소가 먼저 — D-007).
