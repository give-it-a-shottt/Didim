# F-007 공고 입력 · 요구 역량 추출 · 경험 매칭

## 한눈에 보기 (코드 몰라도 OK)
상태: [통과] [됨](2026-11-13) — 구현 · 테스트 · 평가 · 화면 확인(사용자) 끝, 리뷰 4차 [통과].
언제: 5주차
무엇을: 붙여 넣은 공고에서 요구 역량을 뽑고(공고 원문 인용 검사), 역량마다 맞는 내 카드를 근거와 함께 이어요. 근거가 없는 역량은 내 기록 검색 → 카드 후보 찾기로
왜: 지원하기 전에 내 경험 · 기술이 공고와 얼마나 맞는지 확인하려고요.

## 설계 의도 (사용자 확인 — 코드 작성 전에 채움, 문장 정리사 사용)
- 이 기능이 해결하는 문제: 공고를 읽어도 내가 쌓아 온 경험과 기술이 그 공고와 잘 맞는지 한눈에 확인하기 어렵다. 공고의 요구 역량마다 내 경험 카드를 근거와 함께 이어 보여 주어, 지원하기 전에 얼마나 맞는지 확인하게 한다. (사용자 확인, 2026-11-12)
- 정한 것 (사용자 선택, 2026-11-12):
  - 공고 입력: 본문 붙여넣기 + URL은 링크로 저장만(읽지 않음). 사람인 API는 이번 범위에서 뺀다(응답에 상세 요강 본문이 없어 붙여넣기를 대신하지 못함 — 요약 정보 자동 채우기용, D-002대로 승인 후 검토).
  - 매칭: 키워드로 후보 → AI가 판정. 역량마다 내 저장 카드에서 키워드 검색 상위 5장만 보내고(원칙 6), AI는 맞는 카드 · 이유 · 근거가 된 카드 칸 인용을 고른다. 서버가 '보낸 후보 안의 카드인지' · '인용이 그 칸에 글자 그대로 있는지' 검사.
  - 근거 없는 역량: 그 역량으로 내 기록을 검색(F-003)해 노트를 보여 주고 [이 노트에서 카드 후보 찾기](F-006)로 잇는다. 기록이 없으면 [기록 추가]. 빈 카드 직접 만들기는 하지 않는다(F-006 — 카드는 후보에서만).
  - [매칭 다시] 결과가 0개여도 지금처럼 이전 매칭을 지우고 새 결과로 바꾼다. (사용자 확인 2026-11-12, Q-025)
  - 평가는 여기까지 한다. 한도(429) · 시간 초과로 실패한 공고(p02 · p03 · p06)는 다시 재지 않고, 성공한 공고(p01 · p04 · p05)로 판정한다. (사용자 확인 2026-11-13)
  - 사용자당 공고 수 · 매칭에 읽는 저장 카드 수에는 상한을 두지 않는다. (사용자 확인 2026-11-13, Q-026)
  - 실패가 계속 나는 상황을 생각해 숫자 상한은 러프하게 간다 — 지금 값을 그대로 둔다. (사용자 확인 2026-11-13, Q-024)
  - 분석은 요청 두 번(각각 AI 1번): ① 요구 역량 뽑기(역량 이름 · 필수/우대 · 공고 원문 인용, 인용이 공고에 글자 그대로 없으면 버림) ② 매칭. 한 요청에 묶으면 최대 360초라 프록시 상한 200초(T-005)를 넘기 때문. ①이 끝나면 화면이 자동으로 ②를 부르고, ②만 실패하면 ① 결과는 남고 [매칭 다시].
- 완료 기준(무엇이 되면 끝인지): (사용자 확인, 2026-11-12)
  1. 공고를 추가하면 D-day 순 목록에 나오고 상태(준비 · 작성 중 · 제출)를 바꿀 수 있다
  2. 요구 역량마다 공고 원문 인용이 붙는다(검사 통과분만)
  3. 역량마다 맞는 내 카드와 이유 · 카드 칸 인용이 보인다(검사 통과분만)
  4. 근거 없는 역량은 기록 검색 → 카드 후보 찾기로 이어진다
  5. 다른 사용자의 카드가 매칭되지 않는다(D-004). AI 사용량은 하루 상한 · 사용자당 작업 1개(D-018 · D-020)
  6. 평가(D-005): 가상 공고 + 정답지(요구 역량 · 맞는 카드)로 매칭 적중률 · 없는 근거로 만든 매칭 수를 재서 남긴다. 카드는 F-006 평가 노트에 심은 경험을 재사용.
- 화면 · 컴포넌트: 지원 목록(APL_01_001, D-day 순 · 상태 배지) → [공고 추가] 모달(APL_01_002: 회사 · 직무 · 마감일 · URL · 공고 본문 · 자소서 문항) → [분석하기] → 지원 상세(APL_02_001 헤더 + 탭) 공고 분석 탭(APL_02_002: 요구 역량 ↔ 내 카드, 근거 없는 역량 → 기록 검색 · 카드 후보 찾기 / [기록 추가]), 실패 · 한도(APL_02_900).
- API: 지원 만들기 · 목록 · 상세 · 수정(상태 · 마감일) · 삭제, 역량 뽑기(AI), 매칭(AI). 정확한 경로는 구현 때 api-list에.
- 데이터: 버전 파일 0007 — `applications`(회사 · 직무 · 마감일 · URL · 본문 · 상태), `application_questions`(문항 · 글자 수 — F-008이 씀), `posting_requirements`(역량 · 필수/우대 · 공고 인용 위치), `requirement_matches`(카드 · 이유 · 카드 칸 인용), 평가 로그. 모두 user_id 조건(D-004).
