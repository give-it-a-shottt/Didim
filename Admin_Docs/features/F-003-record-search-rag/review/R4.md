- [제안] [추정] 서버 컴포넌트 호출부가 401(세션 만료)과 일반 오류를 구분하지 않아 "검색하지 못했어요" · "노트를 불러오지 못했어요"로 보인다. api-list는 두 API 모두 401 비로그인을 문서화했다. — 위치: frontend/src/lib/records.ts:101-118 searchRecords, :139-166 getNote (401은 `body=null`로 떨어져 `status:"error"`) — 확인한 범위: records.ts · api-list 두 줄. 회원 레이아웃이 매 요청 서버에서 로그인 확인을 해 만료를 먼저 걸러 내는지는 열지 않았다 — [추정 해소: (app) 레이아웃의 세션 확인이 쿠키 유효성까지 백엔드로 확인하는지 보면 확실] 확인이 안 된다면 401일 때 로그인 화면으로 보내거나 별도 상태(`unauthorized`)를 둔다.
- [제안] [추정] `/records/[noteId]`에서 아주 큰 숫자(예: 21자리)는 DIGITS_ONLY를 통과해 `Number()`로 정밀도를 잃은 값이 `/api/notes/{id}`로 가고, 백엔드 `note_id: int`에 범위 제한이 없어 DB 정수 범위를 넘으면 404 대신 500이 될 수 있다(그러면 화면은 404가 아니라 "불러오지 못했어요"). api-list는 "404 없거나 다른 사용자의 노트, 422 숫자 아님"만 적었다. — 위치: frontend/src/app/(app)/records/[noteId]/page.tsx:13, 24, 28 · backend/app/api/notes.py:123-128 — 확인한 범위: 두 파일. 실제 호출은 안 해 봄 — [추정 해소: `GET /api/notes/99999999999999999999`를 PostgreSQL에서 호출해 상태 코드 확인] 고치는 방법: 백엔드 `note_id: int = Path(ge=1, le=2**31-1)`로 422 처리하거나 서비스에서 범위 밖이면 404.

  - 기준 3(누르면 위치 강조) → records/page.tsx:101 링크 `?chunk=#chunk-ID`, [noteId]/page.tsx:46-48, 76-83 mark → 충족.

- api-list ↔ 프론트 ↔ 백엔드 3자 비교
  - `GET /api/search` → 경로 · 메서드 일치(search.py:18, 43 `prefix=/search` + `/api` 접두는 main에서, 프론트 records.ts:103). 쿼리 q(1~200) 일치(config 200 ↔ records.ts:10 200 ↔ api-list). limit 1~5 · 기본 5 일치(프론트는 limit을 보내지 않아 기본 5). 응답 필드 `query, terms, method, results[chunk_id, note_id, note_title, heading_path, start_offset, end_offset, excerpt, matched_terms, score]` 문서 = 백엔드 모델(search.py:24-40) 일치. 프론트는 results의 6개 필드만 읽음(start/end/score 미사용, 지적 1). 에러: 400 공백(프론트가 trim 후 빈 값이면 호출 안 함 → 도달 안 함), 422 길이(프론트가 slice로 방지), 503 → "unavailable" 처리(records.ts:107), 401 → 지적 2. 에러 본문 형식은 `{detail}`(HTTPException)로 문서와 일치, 프론트는 본문을 읽지 않음.
  - `GET /api/notes/{note_id}` → 경로 · 메서드 일치(notes.py:123). 응답 `{id, title, kind, source, created_at, content, chunks[{id, position, heading_path, start_offset, end_offset}]}` 문서 = NoteDetailOut · NoteChunkOut(notes.py:60-76) 일치. 프론트는 id, title, kind, content, chunks[id, heading_path, start_offset, end_offset]만 읽고 타입(number/string) 검증이 일치(records.ts:121-166). 404 → not-found 일치. 422(숫자 아님)는 프론트가 먼저 404로 막음(page.tsx:24). 큰 숫자 · 401 → 지적 3 · 2.
  - 위치 단위(코드 포인트): 백엔드 주석(notes.py:64) ↔ 프론트 text-range.ts `sliceByCodePoints` ↔ api-list 문구 일치(함수 본문은 diff를 열지 않았고 패킷의 "원문 위치 일치" 실행 결과를 근거로 함).
