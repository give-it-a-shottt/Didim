## 지적 묶음 (겹친 것은 하나로)
- A. [주의] [확실] 흔한 낱말 검색이 느리고 시간 · 횟수 상한이 없음 — R2(주의) · R1(제안, 추정). 실측: 사용자당 조각 1만 개, 낱말 1개 3.3초 · 4개 6.4초. 맞는 행마다 비슷함 계산이 최대 3번(WHERE 재확인 + CASE 안 연산자 + word_similarity). statement_timeout이 없고, 동기 함수라 DB 연결 · 스레드를 붙잡음. 고치는 방법: ① 서브쿼리에서 낱말별 word_similarity를 한 번만 계산(+ `OFFSET 0`) ② `SET LOCAL statement_timeout`(초 수는 사용자 결정) + 시간 초과 응답 ③ (선택) 사용자별 검색 횟수 상한 → 열린 질문 후보. `backend/app/search/keyword.py`
- B. [주의] [확실] 서버 컴포넌트 → FastAPI 호출 코드(BACKEND_URL · 쿠키 붙이기 · fetch)가 `lib/auth.ts`와 `lib/records.ts` 두 벌 — R1. 고치는 방법: 공통 `fetchBackendAsUser`(예: `lib/backend.ts`)로 합침.
- C. [주의] [확실] 검색 로그 저장 실패 → 롤백 + 결과는 그대로 돌려주는 분기에 테스트 없음 — R3. `backend/app/services/search_service.py` `_save_log`
- D. [주의] [확실] 화면의 오류 분기(백엔드 500 · 연결 실패 · 응답 모양 틀림)와 노트 상세 오류 분기를 Playwright가 실행하지 않음(가짜 백엔드가 503만 흉내) — R3.
- E. [제안] [추정] 아주 큰 노트 ID(2^31 이상)는 404 대신 500(DB 정수 범위 초과), 화면은 21자리 이상이면 정밀도를 잃음 — R2 · R4. 고치는 방법: 백엔드 `Path(ge=1, le=2_147_483_647)` 또는 범위 밖 404, 화면 `/^\d{1,10}$/`.
