# D-021 노션은 공개 OAuth로 연결하고, 토큰은 암호화해 사용자당 하나로 둔다

## 한눈에 보기 (코드 몰라도 OK)
상태: [통과] 사용자가 골랐어요(2026-11-12).
무엇을: 설정에서 [연결]을 누르면 노션 동의 화면에서 페이지를 고르고, 디딤은 받은 열쇠(토큰)를 잠가서(암호화) 저장해요. 열쇠가 만료되면 알아서 새것으로 바꾸고, 다시 해도 안 되는 경우(노션이 열쇠가 무효라고 함 · 저장한 열쇠를 풀 수 없음 · 새 열쇠도 거절됨)에만 '끊김'으로 바꿔 다시 연결하게 해요. 가져오기는 한 사람당 한 번에 하나만 돌아요.
왜: 노션에 정리하는 사람이 내보내기 없이 바로 가져오게 하려고요(F-005). 열쇠를 사용자가 직접 붙여 넣는 방식보다 실제 서비스 흐름에 가깝고, 잠깐의 노션 장애로 멀쩡한 연결이 끊기지 않게 하려고요.

## 개발자 상세

### 상황
- F-005(노션 연결)를 만들며 연결 방식 · 토큰 보관 · 끊김 기준 · 동시 가져오기를 정해야 했다. 노션 공개 통합은 OAuth 2.0이고, 갱신할 때 갱신 토큰도 새것으로 바뀐다(rotation). 접근 토큰 회수 API(`POST /v1/oauth/revoke`)가 있다. 개발용 리디렉트는 `http://localhost`만 허용(127.0.0.1 안 됨) — 배포 없이 연결 가능.

### 후보 — 연결 방식
| | A. 공개 OAuth (선택) | B. 토큰 붙여넣기 | C. 내보내기 파일 올리기 |
|---|---|---|---|
| 장점 | 실제 서비스 흐름, 페이지를 노션 화면에서 고름, 재연결 흐름이 자연스러움 | 가장 빠름 | API 불필요 |
| 단점 | 공개 통합 등록 · state · 토큰 갱신 · 암호화가 필요 | 사용자가 비밀 값을 직접 다룸 | 지금도 md로 올릴 수 있어 새로 생기는 게 적음 |

### 결정
- 연결: A. OAuth state에 연결을 시작한 사용자 번호를 서명해 담고, 콜백 때 지금 로그인한 사용자와 같은지 확인한다(다른 사람의 노션이 내 계정에 붙지 않게). 비로그인으로 연결 · 콜백 주소를 열면 /login.
- 토큰 보관: `notion_connections`에 사용자당 1줄, 접근 · 갱신 토큰을 Fernet(`cryptography`)으로 암호화. 키는 환경변수 `NOTION_TOKEN_KEY`. API 응답 · 로그 · repr에 토큰을 내보내지 않는다.
- 갱신 · 끊김 기준: 만료 시각을 알면 미리, 모르면 401 뒤 한 번 갱신. '끊김'(토큰 지움 → 설정에서 다시 연결)은 다시 해도 안 되는 세 경우만: ① 노션이 갱신 토큰을 무효(`invalid_grant`)라고 함 ② 저장한 토큰을 풀 수 없음(암호화 키가 바뀜 · 값이 깨짐) ③ 갱신한 토큰도 401(그새 다시 연결해 토큰이 바뀌었으면 끊지 않음). (문구 넓힘 — 사용자 확인 2026-11-12, F-005 3차 리뷰) 노션 서버 오류 · 네트워크 실패 같은 일시 장애는 연결을 유지하고 "잠시 후 다시"(502), 서버 설정 문제(`invalid_client`)는 503. 토큰 요청은 다시 보내지 않는다(응답만 잃었는데 다시 보내면 바뀐 갱신 토큰이라 끊김이 됨). 동시 갱신은 연결 줄을 잠그고 "그새 바뀌었는지" 본 뒤 갱신.
- 동시 가져오기: 사용자당 하나(`importing_since`, 5분 지나면 새 요청이 가져감). AI 작업 하나(D-020)와는 따로 센다 — 노션 가져오기는 AI를 부르지 않음.
- 끊기: 노션에서도 접근 토큰 회수를 한 번 시도하고(실패해도 넘어감) 우리 쪽 토큰을 지운다. 가져온 노트는 남는다.
- 가져오기 범위: 한 번 가져오기 + 중복 안내, 고른 페이지만(하위 페이지는 따로). 상한은 F-005 feature.md(사용자 확인).

### 결과로 생기는 제약
- 암호화 키를 바꾸면 기존 토큰을 풀 수 없어 그 사용자는 노션을 다시 연결해야 한다. 키 교체 기능(MultiFernet 등)은 만들지 않는다 — 바꿀 계획 없음(사용자 확인 2026-11-12, F-005 2차 리뷰).
- 실제로 연결하려면 노션 개발자 페이지에 공개 통합 등록 + `.env`의 `NOTION_CLIENT_ID` · `NOTION_CLIENT_SECRET` · `NOTION_TOKEN_KEY`가 필요하다.
- 가져오기는 요청 한 번에 처리(Q-008)하고 시간 예산 140초(Next 프록시 200초 안, T-005).

### 이 결정을 바꿔야 하는 조건
- 노션 OAuth가 갱신 토큰에 유예 시간을 주거나 rotation을 없애면 토큰 요청 재시도를 다시 검토.
- 여러 사람이 쓰게 되면(Q-019는 '공개 배포 없음'으로 닫힘) 노션 호출 간격 · 작업 스레드를 요청끼리 나눠 쓰는 것과 키 교체를 다시 검토(F-005 2차 리뷰 R2).
- 노션에서 고친 내용을 다시 가져와야 하면(2차) 인용 위치가 깨지는 문제와 함께 다시 정한다.
