## 지적
- [신규] [제안] [추정] `npm ci`가 막는 범위가 문서보다 좁다 — lockfile에 없는 버전은 막지만 lockfile에 있는 패키지의 설치 스크립트는 그대로 돌고 그때도 빌드 환경변수가 보인다. '환경변수를 같이 보는 빌드의 위험 줄이기'만 쓰면 과하게 읽힘. `npm ci`는 node_modules를 새로 깔아 빌드 캐시 이득이 조금 줄어듦(사소). — D-033 · deployment.md · 테스트 주석 — 고치는 방법: 문구를 '새 버전이 몰래 들어오는 것만 막고 설치 스크립트는 그대로'로. `--ignore-scripts`는 미리보기로 시험할지 사용자가 정함. → 문구 반영, `--ignore-scripts`는 다음에.
- [신규] [제안] [추정] `process.env.VERCEL`은 로컬에서도 켜질 수 있다 — `vercel env pull`이 `.env.local`에 `VERCEL="1"`을 적으면 로컬 next dev · start · Playwright에서 rewrites가 꺼져 /api/*가 404(막히는 쪽이라 보안 문제 아님, 원인 찾기 어려움). env pull은 운영 비밀값을 로컬 파일로 내려받는 일이기도. — 고치는 방법: 체크리스트 '알아 둘 것'에 'frontend에서 vercel env pull 하지 않기'. → 반영.
