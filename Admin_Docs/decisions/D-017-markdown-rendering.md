# D-017 노트 원문은 react-markdown으로, 조각 단위로 그린다

## 한눈에 보기 (코드 몰라도 OK)
상태: [통과] 사용자가 요청하고 골랐어요(2026-11-10).
무엇을: 노트 상세의 원문을 `##` · `**` 같은 기호 그대로가 아니라 제목 · 목록 · 링크로 읽기 좋게 보여 줘요. 원문은 조각(제목 단위)마다 따로 그려서, 이상하거나 아주 큰 원문 하나가 서버를 멈추지 않게 해요.
왜: 원문을 읽기 쉽게 보여 달라는 요청(사용자, 2026-11-10). 조각 단위 · 크기 상한은 3차 리뷰에서 1MB 원문이 서버를 1~13초 멈추고 `>` 반복 원문이 오류를 내는 것을 실측해서 정함(사용자 확인).

## 개발자 상세

### 후보
| | A. react-markdown + remark-gfm | B. marked 등으로 HTML 문자열 만들기 | C. 직접 파서 |
|---|---|---|---|
| 방식 | 마크다운 → React 요소(서버 컴포넌트 가능) | HTML 문자열 → dangerouslySetInnerHTML | 제목 · 목록만 직접 처리 |
| 장점 | 원문 속 HTML을 실행하지 않음(기본), 위험한 링크 주소를 기본으로 비움, 컴포넌트로 토큰 클래스 적용 | 빠름 | 패키지 없음 |
| 단점 | 패키지 2개 | XSS를 따로 막아야 함(sanitize 패키지 추가) | 표 · 코드 블록 등 빠짐, 유지보수 |

### 결정
- A. `react-markdown` 10.1.0 + `remark-gfm` 4.0.1, 버전 고정(`--save-exact`). npm audit(운영 의존성) 0건(2026-11-10).
- `frontend/src/components/note-markdown.tsx`: 원문을 조각 경계로 나눠 조각마다 그림. 코드 울타리가 경계에 걸리면 닫힐 때까지 다음 조각과 합침. 원문이 200,000자를 넘으면 마크다운 대신 글자 그대로(강조 유지).
- 안전장치(4차 리뷰 뒤, 사용자 확인): 3,000자 넘는 묶음(조각이 아닌 빈 구간 포함) · 줄 앞 `>` / 들여쓰기 20단 넘는 묶음 · 노트 하나 그리는 시간 300ms 넘은 뒤의 묶음은 글자 그대로. 울타리 합치기도 3,000자까지.
- 원문 속 HTML은 실행하지 않음, 링크는 새 탭 + `noopener noreferrer`, 이미지는 불러오지 않고 "이미지: 설명" 링크로.
- 원문 속 제목은 h3부터(화면마다 h1 하나, 설계 원칙 8).

### 결과로 생기는 제약
- 조각을 따로 그리므로 조각을 넘어서 이어지는 마크다운(번호 목록 번호 이어짐, 다른 조각에 정의된 참조 링크)은 끊길 수 있다.
- 200KB가 넘는 원문은 글자 그대로 보이고, 브라우저가 그리기까지 약 5초 걸린다(서버 응답은 0.1초 안, 2026-11-10 Playwright 실측).

### 이 결정을 바꿔야 하는 조건
- 조각 경계에서 끊기는 표시가 자주 문제가 될 때, 또는 원문 편집 기능이 생길 때(편집기 라이브러리와 함께 다시 고름).
