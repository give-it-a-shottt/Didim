# 프론트엔드 스터디 4주차 회고

## 내가 맡은 일: 상품 목록 렌더링 개선
스터디에서 같이 만드는 쇼핑몰 연습 앱에서 상품 목록 페이지가 필터를 바꿀 때마다 버벅였다. 내가 이 페이지를 맡고 있어서 다음 모임 전까지 원인을 찾아 오기로 했다.

React DevTools Profiler로 녹화해 보니 필터 하나를 바꿔도 상품 카드 120개가 전부 다시 그려지고 있었다. 부모 컴포넌트가 렌더링될 때마다 새 함수를 만들어 넘기는 게 원인이었다. 카드 컴포넌트를 `React.memo`로 감싸고 핸들러를 `useCallback`으로 고정했다.

Profiler 기준으로 필터 변경 한 번의 렌더링 시간이 180ms에서 40ms로 줄었다. 모임에서 Profiler 화면을 보여 주며 설명했더니 다른 팀원도 자기 페이지에 같은 방법을 썼다.

## 스터디 발표 자료 정리
4주 동안 발표 자료가 노션, 구글 드라이브, 각자 블로그에 흩어져 있어서 지난 주제를 다시 찾기 어려웠다.

내가 발표 자료를 깃허브 저장소 하나에 모으자고 제안했고, 주차별 폴더와 README 목차를 만들었다. 그동안의 자료 14개를 직접 옮기고, 앞으로는 발표자가 PR로 올리는 규칙을 정했다.

## 강의 메모: 렌더링 최적화 사례
강의에서 강사가 예전 회사에서 무한 스크롤 목록을 react-window로 가상화해서 메모리 사용량을 절반으로 줄였다는 사례를 들려줬다. 목록이 수천 개일 때는 memo보다 가상화가 효과가 크다고 했다.
