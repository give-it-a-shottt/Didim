# 북마크 서비스 회고 — 목록 API가 느렸던 일

## 목록 API가 느려진 문제
북마크가 300개쯤 쌓인 테스트 계정으로 목록 화면을 열면 3초 넘게 걸렸다. 친구들에게 시연하기로 한 날이 이틀 남아서 그 전에 고쳐야 했다.

SQL 로그를 켜 보니 목록 한 번에 쿼리가 301번 나가고 있었다. 북마크를 가져온 뒤 태그를 북마크마다 따로 불러오는 N+1 문제였다. SQLAlchemy 관계에 `selectinload`를 붙여 태그를 한 번에 가져오도록 바꿨고, 같은 실수를 막으려고 쿼리 수를 세는 테스트를 하나 추가했다.

고친 뒤 같은 계정에서 쿼리는 2번, 응답은 0.2초로 줄었다. 시연 날에도 목록이 바로 떴다.

## N+1이 뭔지 정리
N+1은 목록을 가져오는 쿼리 1번에 항목마다 쿼리가 1번씩 더 나가는 패턴이다. ORM이 관계를 지연 로딩할 때 흔히 생긴다. 조인으로 한 번에 가져오는 joinedload나 IN 쿼리로 묶어 가져오는 selectinload로 해결한다.
