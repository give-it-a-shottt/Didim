## 지적 (있을 때)
- [신규] [제안] [추정] [이 문항 완료](PATCH)만 조건 없이 ORM으로 갱신한다. 같은 초안을 [다시 쓰기](save_draft → _replace_draft가 옛 Draft 줄을 지움)가 지우는 순간과 겹치면, `_get_draft`로 읽은 뒤 커밋 때 UPDATE가 0줄이 되어 SQLAlchemy `StaleDataError` → 처리되지 않은 500이 날 수 있다(내부 정보는 안 나감 — FastAPI 기본 "Internal Server Error"). 화면의 `refetchIfStale`은 409 · 404만 다시 받으므로 이 경우 새로 받지 않는다. 겹치는 틈은 save_draft 커밋 순간(수 ms)뿐이라 실제로 날 일은 드물다. 또 version을 보지 않으므로 다른 탭이 고친 직후의 내용을 못 본 채 '완료'로 표시할 수 있다(이건 설계상 'version은 그대로' — 테스트 test_complete_marks_and_clears로 의도 확인, 보안 문제 아님). — 위치: backend/app/services/draft_service.py `set_draft_completed` — 확인한 범위: diff의 draft_service.py · draft_view.py `_get_draft` · drafts.py `complete_draft_endpoint` · draft-workspace.tsx `complete`/`needsRefetch`(직접 재현은 안 함). [확실]이 되려면: PostgreSQL 테스트에서 `_get_draft` 뒤 다른 세션이 Draft를 지우고 커밋한 다음 `set_draft_completed`의 commit이 StaleDataError를 내는지 확인. — 고치는 방법: `update(Draft).where(Draft.id == draft_id, Draft.user_id == user_id).values(completed_at=...)`의 rowcount로 바꾸고 0이면 DraftNotFound(404 → 화면이 새로 받음). 필요하면 화면이 version을 같이 보내 다르면 409.
