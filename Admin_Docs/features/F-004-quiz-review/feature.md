## 설계 의도 (사용자 확인 — 코드 작성 전에 채움, 문장 정리사 사용)
- 이 기능이 해결하는 문제: 공부 기록을 올려도 다시 보지 않아 잊힌다. 내 기록에서 근거가 확인된 문제를 만들고, 정해진 간격으로 다시 풀게 해서 기억에 남긴다. (사용자 확인, 2026-11-10)
- 정한 것 (사용자 확인, 2026-11-10 — 선택지로 받음):
  - 문제는 노트 상세의 [문제 만들기]로 노트 하나씩 만든다(요청 한 번에, 백그라운드 작업 · 이어 보기 없이). 기록 추가 직후 자동 만들기는 Q-008을 정한 뒤.
  - 근거 검사: 문제마다 근거 조각과 "정답의 근거가 되는 원문 문장"을 같이 받고, 그 문장이 조각 안에 글자 그대로 있는지 서버가 확인한다. 없으면 그 문제는 버리고 버린 개수를 로그로 남긴다(평가 수치). 해설에는 근거 칩 → 노트 상세 위치 강조(F-003).
  - 복습 단위: 기록 · 복습 홈의 '오늘 복습'(모든 노트에서 오늘 차례인 문제를 한 세션으로) + 노트 상세의 [이 노트 풀기](그 노트 문제만).
  - 문제 수: 조각마다 1개, 노트당 최대 10개(짧은 조각은 건너뜀).
- 완료 기준(3주차): (사용자 확인, 2026-11-10)
  1. 노트 상세 [문제 만들기] → 조각마다 1개(짧은 조각 건너뜀), 노트당 최대 10개, 객관식(4지) · OX.
  2. 문제마다 근거 조각 + 원문 인용 문장을 저장하고, 인용이 조각 안에 글자 그대로 없으면 버리고 버린 수를 기록한다.
  3. 해설에 근거 칩 → 누르면 노트 상세 위치 강조.
  4. 풀면 채점 · 다음 복습일(당일 → 1 → 3 → 7 → 14일). 틀리면 오답노트, 2번 연속 맞히면 빠짐.
  5. 기록 · 복습 홈 '오늘 복습 N' → 한 세션, 노트 상세 [이 노트 풀기] → 그 노트만.
  6. AI 호출은 사용자당 하루 상한(30회) 안에서, 형식 오류는 재시도 후 실패 안내. 다른 사용자의 문제는 안 보인다.
  7. 가상 노트(D-005)로 '정답 · 해설이 원문과 맞는 비율'과 '버려진 문제 비율'을 재서 기록한다.
- 화면 · 컴포넌트: (IA 화면 ID 참고 — REV_01_001 · 002 · 003, REV_02_001 · 002, REV_03_001, REV_01_900)
- API: (사용자 확인, 2026-11-10) `POST /api/notes/{id}/quizzes`(문제 만들기), `GET /api/notes/{id}/quizzes`(그 노트 문제), `GET /api/reviews/today`(오늘 복습), `POST /api/quizzes/{id}/answer`(답 제출 → 채점 · 해설 · 근거 · 다음 복습일), `GET /api/wrong-answers`(오답노트). 답 제출은 화면에서 TanStack Query(D-012).
- 데이터: (사용자 확인, 2026-11-10) 버전 파일 0004 — `quizzes`(노트 · 근거 조각, 유형, 문제, 보기, 정답, 해설, 근거 인용 문장 + 원문 위치), `quiz_reviews`(다음 복습일 · 간격 단계 · 연속 정답 수 · 오답노트 여부), `quiz_attempts`(고른 답 · 맞음 · 시각), `quiz_generation_logs`(요청 · 남긴 · 버린 수와 이유, 호출 · 토큰 — 평가 · 하루 상한). 모두 user_id(FK CASCADE) 조건(D-004).
