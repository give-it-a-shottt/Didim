## 지적

- [위험] [확실] Content-Length가 없는 요청(chunked 전송)은 크기 상한 없이 끝까지 받고, 그것도 로그인 확인 전에 받는다. 미들웨어는 머리말이 없으면 통과시키고(`upload_limit.py:23-24`, 테스트 `_run_size_guard(None) == 200`), FastAPI는 폼 본문을 의존성(`get_current_user`)보다 먼저 파싱한다(fastapi `routing.py:455` → `:511`). starlette는 파일 파트 크기 상한이 없고, 파일마다 1MB까지 메모리(SpooledTemporaryFile)에 두며 파일 1,000개까지 받는다. 그래서 비로그인 요청 하나가 최대 약 1GB 메모리(1MB 미만 파일 1,000개) 또는 제한 없는 임시 디스크를 쓰게 할 수 있다. `notes.py:80`의 합계 확인은 다 받은 뒤라 자원 소모를 막지 못하고, 비로그인이면 거기까지 오지도 않는다(401). — 위치: backend/app/api/upload_limit.py:22-26, backend/app/api/notes.py:61-80 — 확인한 범위: 실제 파일과 설치된 fastapi `routing.py` · starlette `formparsers.py`를 읽어 확인(실행은 안 함). Next.js 프록시가 chunked 요청을 그대로 백엔드에 넘기는지는 확인 안 함(백엔드에 직접 닿는 경로가 있으면 그대로 해당). — 고치는 방법: 이 경로에서 (a) Content-Length가 없으면 411로 거절하거나(브라우저 FormData는 항상 머리말을 보내고, 패킷의 22MB 실험으로 Next 경유도 머리말이 전달됨을 확인함), (b) 순수 ASGI 미들웨어로 `receive`를 감싸 누적 바이트가 `MAX_IMPORT_REQUEST_BYTES`를 넘는 순간 413으로 끊는다. (b)가 머리말을 속이는 경우까지 막아 더 안전함. 테스트: 머리말 없는 요청이 본문을 읽기 전 거절되는지.

- [위험] [확실] 제목 정규식 `_HEADING`이 공백이 긴 제목 줄에서 제곱 시간이 걸린다(ReDoS). `(.+?)`(게으른 반복)의 위치마다 `(?:[ \t]+#+)?[ \t]*$`가 남은 공백을 다시 훑기 때문. 측정: `"# a" + 공백 n개 + "b"` 한 줄에서 n=2,000 → 0.025초, 4,000 → 0.091초, 8,000 → 0.361초, 16,000 → 1.49초(2배마다 약 4배). 1MB짜리 한 줄이면 약 1.5시간으로 추정되고, 파일마다 `find_title`(markdown.py:110)과 `split_markdown`(chunking.py:119)에서 두 번 돌며, 파이썬 `re`는 실행 중 GIL을 놓지 않아 그동안 서버 전체가 멈춘다. 로그인한 사용자라면 .md 파일 하나로 가능. — 위치: backend/app/importers/markdown.py:21 (호출 :62) — 확인한 범위: 실제 정규식을 레포 venv에서 n=2,000~16,000으로 직접 실행해 측정(scratchpad 스크립트, 테스트 스위트는 안 돌림). 1MB 시간은 측정값으로 외삽함. — 고치는 방법: 겹치는 반복을 없앤다. 예) 정규식은 `^ {0,3}(#{1,6})[ \t]+(.*)$`로 글 전체만 잡고(끝에 `$` 외 조건이 없어 실패 · 되돌아가기가 없음), 닫는 `#`과 끝 공백은 파이썬 문자열 처리(`rstrip(" \t")` → 끝의 `#` 묶음 앞이 공백이면 떼기)로 한다. 그리고 제목으로 볼 줄 길이에 상한(예: 1,000자)을 둔다. 회귀 테스트: `"# a" + " " * 200_000 + "b"`가 1초 안에 끝나는지.

- [위험] [확실] 제목 경로(heading_path)에 길이 상한이 없어 입력보다 수천 배 큰 데이터가 생긴다. 제목 글은 자르지 않고 스택에 넣어(`chunking.py:49`) 구역마다 새 문자열로 이어 붙이고(`:50`), 조각마다 그대로 저장한다(`note_service.py:59-69`). 노트 제목만 255자로 자른다(markdown.py:111). 측정: `"# " + "x"×20KB` 다음에 `"### a\nb\n"` 4,000개(입력 52KB) → 조각 4,000개, heading_path 합계 8,196만 글자(약 1,560배). 1MB 파일(제목 500KB + 작은 구역 약 6.5만 개)이면 heading_path가 수백억 글자가 되어 DB에 닿기 전에 메모리가 바닥나 프로세스가 죽는다. 로그인한 사용자 요청 하나로 가능. — 위치: backend/app/services/chunking.py:49-50, backend/app/services/note_service.py:59-69 — 확인한 범위: `split_markdown`을 레포 venv에서 작은 크기로 실행해 측정, 1MB는 외삽함. — 고치는 방법: 경로에 넣는 제목 글을 자르고(예: 단계마다 `TITLE_MAX_CHARS` 255자), heading_path 전체에도 상한(예: 1,000자)을 둔다. 상수는 config.py에 둔다. 테스트: 긴 1단계 제목 + 많은 하위 구역에서 heading_path 길이가 상한 이하인지.

- [주의] [확실] DB 저장 실패 로그에 노트 원문 · 제목 일부가 남는다. `logger.exception`(import_service.py:128)은 예외 메시지를 함께 남기는데, 엔진을 `hide_parameters` 없이 만들어서(session.py:32) SQLAlchemy 오류 메시지에 `[parameters: ...]`로 INSERT 값(제목 · content · heading_path, 값마다 앞부분 약 300자)이 들어간다(sqlalchemy `exc.py:589-597`). 코드 주석과 패킷 결정 5("로그에는 user_id만")와 다르다. — 위치: backend/app/services/import_service.py:128, backend/app/db/session.py:32 — 확인한 범위: 실제 파일과 설치된 sqlalchemy `exc.py`를 읽어 확인(실제 오류를 일으켜 보지는 않음). — 고치는 방법: `create_engine(..., hide_parameters=True)`로 바꾼다(SQL 문은 남고 값만 가려짐). 또는 이 자리에서 `logger.error("노트 저장 실패 (user_id=%s, %s)", user_id, type(exc).__name__)`처럼 예외 종류만 남긴다. 앞쪽이 다른 코드 경로에도 적용되어 더 나음.

- [주의] [추정] 조각 수에 상한이 없어 파일 하나가 많은 행을 만든다. 측정: `"### a\nb\n"`만으로 된 1MB 파일 → 조각 131,072개(나누기만 0.72초). 20개를 올리면 요청 하나에서 약 260만 행을 ORM 객체로 만들어 한 트랜잭션씩 INSERT하고, 그동안 스레드 하나와 DB 연결을 잡는다. 2주차에 조각마다 임베딩을 붙이면 호출 비용도 조각 수에 비례한다(설계 원칙 4). — 위치: backend/app/services/chunking.py:116-, backend/app/services/import_service.py:102, backend/app/services/note_service.py:59-69 — 확인한 범위: 나누기만 실행해 측정. DB 저장 시간과 메모리는 측정 안 함. 요청 한 번 처리 구조는 Q-008 임시 처리와 관련, 조각 수 무제한은 그와 별개. — [확실]이 되려면: PostgreSQL 개발 DB에 위 1MB 파일을 1개 · 20개 올려 처리 시간과 서버 메모리를 잰다. — 고치는 방법: 노트당 조각 수 상한(예: 2,000, config.py 상수)을 두고 넘으면 그 파일만 실패 이유와 함께 돌려준다. 아주 작은 구역을 합치는 방식은 나누기 규칙(설계 의도)을 바꾸는 것이므로 하려면 OPEN_QUESTIONS에 먼저 적는다.

- [제안] [확실] Content-Length가 있어도 비로그인 요청이 21MB까지 본문을 보내 임시 파일로 받게 한 뒤에야 401을 받는다(본문 파싱이 인증보다 먼저, fastapi `routing.py:455` → `:511`). 지적 1을 고쳐도 남는 부분. — 위치: backend/app/api/upload_limit.py:22-26 — 확인한 범위: 설치된 fastapi 코드를 읽어 순서 확인(실행 안 함). — 고치는 방법: 같은 미들웨어에서 이 경로에 세션 쿠키가 없으면(가능하면 토큰 서명까지 확인) 본문을 읽기 전에 401을 돌려준다.
