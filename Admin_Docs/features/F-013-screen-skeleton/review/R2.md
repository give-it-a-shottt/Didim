## 지적 (있을 때)
- [신규] [제안] [확실] 접힌 상태로 새로 고침하면 사이드바 폭은 첫 화면부터 56이지만, [사이드바 펼치기] 버튼의 화살표 회전 · `aria-label` · `aria-expanded`는 하이드레이션이 끝날 때까지 "펼침" 상태(왼쪽 화살표 · "사이드바 접기" · `aria-expanded=true`)로 보인다. `useSyncExternalStore`는 하이드레이션 때 `getServerSnapshot`(`() => false`)을 쓰고, 그다음에 클라이언트 값으로 다시 그리기 때문이다. 화면 배치는 CSS가 맡아서 레이아웃은 흔들리지 않는다(rotate는 배치에 영향 없음). 다만 아이콘이 한 번 뒤집히는 작은 깜빡임이 있고, 얼마나 오래 보이는지는 하이드레이션 시간에 달렸다(길이는 [추정] — 느린 기기에서 성능 패널로 재면 [확실]). — 위치: `frontend/src/components/sidebar-toggle.tsx`의 `useSyncExternalStore(subscribe, isCollapsed, () => false)`와 `<Icon … className={collapsed ? "rotate-180" : undefined} />` — 확인한 범위: 패킷의 sidebar-toggle.tsx 전문, Next 16 문서 preventing-flash-before-hydration.md의 Themes · Syncing with React state 부분 — 고치는 방법: 회전은 JS 상태가 아니라 CSS가 html 속성을 직접 보게 한다. 예: globals.css에 `@custom-variant sidebar-collapsed (html[data-sidebar-collapsed] &);`를 두고 아이콘에 `sidebar-collapsed:rotate-180`을 쓴다(또는 Tailwind v4 `in-[[data-sidebar-collapsed]]:rotate-180`). 이렇게 하면 인라인 스크립트가 속성을 붙이는 순간 첫 화면부터 맞게 보인다. 이름(`aria-label` · 툴팁)은 지금처럼 `useSyncExternalStore`로 두어도 된다. 눈에 보이지 않고 하이드레이션 직후 바로 고쳐진다.

## 체크 항목별 근거 (항상 작성, 항목당 한 줄)
- 보안·프론트 XSS(위험한 HTML 삽입) → layout.tsx `<script dangerouslySetInnerHTML={{ __html: SIDEBAR_INIT_SCRIPT }}>`, sidebar-state.ts → 문제 없음. 빌드할 때 정해지는 상수 세 개를 `JSON.stringify`로 넣은 고정 문자열이다. 사용자 입력 · 요청 값 · localStorage 값은 스크립트 본문에 섞이지 않는다(localStorage 값은 `===` 비교에만 쓰고 DOM에 넣지 않으며, 속성 값도 빈 문자열로 고정). `</script>` 같은 끊김 문자도 없다.
- 보안·프론트 CSP 영향 → 프론트엔드 전체(node_modules 제외)를 `Content-Security-Policy|nonce|script-src`로 검색 → 지금은 CSP가 없어 영향 없다. 나중에 `'unsafe-inline'`이 없는 CSP를 넣으면 이 스크립트에 nonce나 해시(본문이 고정이라 sha256 해시가 된다)가 필요하다(Next 문서 242행).
- 보안·프론트 토큰 저장 위치 → sidebar-toggle.tsx · sidebar-state.ts → 문제 없음. localStorage에는 `didim:sidebar="collapsed"` 한 값만 둔다. 토큰 · 개인정보는 없다. 세션은 그대로 httpOnly 쿠키다(sidebar.spec.ts에서 확인).
- 보안·프론트 공개 환경변수에 비밀값 노출 → 바뀐 파일 전체 → 해당 없음(새 환경변수 없음).
- 보안·프론트 권한 없는 화면 접근 차단 → layout.tsx · app-sidebar.tsx diff → 영향 없음. 인증 경로는 바뀌지 않았고, 루트 레이아웃 스크립트는 공개 화면에서도 html 속성 하나만 붙인다. `suppressHydrationWarning`은 `<html>` 한 요소의 속성 차이만 넘어가고 자식 요소에는 적용되지 않는다.
- 보안·백엔드(인증 · 권한 · 입력 검증 · SQL 인젝션 · CORS · 비밀키 · 에러 응답) → 패킷 "백엔드 변경 없음" → 해당 없음.
- 보안·공통 패키지 취약점 · 오래된 버전 → 패킷 바뀐 파일 목록 → 해당 없음(패키지 추가 · 업그레이드 없음).
- 보안·공통 Admin_Docs · 코드에 민감 정보 → architecture.md 추가한 줄, 새 파일 3개(테스트의 세션 값은 가짜 백엔드용 고정 문자열) → 문제 없음.
- 성능·프론트 불필요한 리렌더링 → sidebar-toggle.tsx · app-sidebar.tsx → 문제 없음. `subscribe`는 모듈 단위 함수라 렌더링할 때마다 다시 구독하지 않는다. 바꾸면 SidebarToggle 하나만 다시 그리고, 사이드바 폭 · 배치는 CSS(html 속성 + `sidebar-open` 변형)가 맡는다. useLayoutEffect는 마운트 때 한 번만 돈다.
- 성능·프론트 레이아웃 흔들림 · 깜빡임 → layout.tsx head 스크립트, globals.css 변형 → 폭 · 배치는 첫 화면 전에 정해져 흔들림이 없다. 버튼 아이콘 회전만 하이드레이션 전까지 다르게 보인다(위 [제안]).
- 성능·프론트 이벤트 구독 해제 → sidebar-toggle.tsx `subscribe` → 문제 없음(같은 함수 참조로 removeEventListener를 돌려준다).
- 성능·프론트 번들 크기 → 새 클라이언트 컴포넌트 1개(작음), sidebar-state.ts는 상수만 → 문제 없음.
- 성능·프론트 CSS 선택자 비용 → globals.css `sidebar-togglable`(새 `body:not(:has(...))`) → 문제 없음. 기존 `sidebar-open`과 같은 `:has()` 조건을 한 번 더 쓰는 정도이고, 새로 무거운 선택자는 없다.
- 성능·프론트 이미지 최적화 → 해당 없음(이미지 변경 없음).
- 성능·프론트 과도한 API 호출 → 해당 없음(새 호출 없음. 상태 select는 CSS만 바뀜).
- 성능·백엔드(N+1 · 인덱스 · 페이지네이션 · 무거운 동기 작업) → 해당 없음(백엔드 변경 없음).

확인한 범위: 체크리스트 R2-security-performance.md, 리뷰 패킷 ui-r1-packet.md 전체, `frontend/node_modules/next/dist/docs/01-app/02-guides/preventing-flash-before-hydration.md`(CSP 메모 · Themes · Syncing with React state 부분), `frontend` 안(node_modules 제외) CSP · nonce 검색. 그 밖의 파일은 열지 않았다. 테스트는 다시 돌리지 않았다.
