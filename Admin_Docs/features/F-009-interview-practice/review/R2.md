- [신규] [주의] [확실] `LLM_BASE_URL` 하나를 exaone · nvidia · local이 같이 써서, provider를 넘겨 부르는 실행(`llm_ping exaone` · `interview_eval exaone` · `draft_eval exaone`)에서 한 회사의 키가 다른 회사 주소로 갈 수 있음 — 위치: `backend/app/llm/settings.py` 120행(exaone), 139행(nvidia, 이번에 추가), 152행(local). 예: 메인 nvidia를 위해 `LLM_BASE_URL`을 NVIDIA 쪽 https 주소로 적어 둔 채 `interview_eval exaone`을 돌리면 `EXAONE_API_KEY`가 그 주소로 Bearer 헤더에 실려 나감(반대도 같음). https 강제(`_check_base_url`, 84~91행)와 리다이렉트 안 따라감(`openai_compat.py` 108~109행)은 막지 못하는 경로. D-027이 "provider를 넘겨 두 모델을 비교"를 목적으로 `NVIDIA_MODEL`은 따로 뺐지만 주소는 따로 빼지 않음. 지금 `.env.example`에는 `LLM_BASE_URL`이 주석이라 기본 설정에서는 일어나지 않음(실제 발생 가능성 낮음). — 확인한 범위: 패킷 diff(settings.py · .env.example · llm_ping 문서), `settings.py` 50~157행, `openai_compat.py`의 follow_redirects · Authorization · 429 줄(grep). `.env`는 열지 않아 실제로 `LLM_BASE_URL`을 적었는지는 모름. — 고치는 방법: (가장 작게) `LLM_BASE_URL`은 `local`일 때만 읽고 exaone · nvidia는 공식 주소 상수만 쓰기, 또는 `EXAONE_BASE_URL` · `NVIDIA_BASE_URL`처럼 provider별 이름으로 나누기. 어느 쪽이든 테스트 한 줄 — "`LLM_BASE_URL`을 다른 주소로 둬도 `load_llm_settings("exaone").base_url == EXAONE_BASE_URL`"(test_nvidia_model_does_not_leak_into_exaone와 같은 모양). 주소 바꾸기 기능을 남길지는 사용자 선택이라, 바꾸기 전에 확인.
