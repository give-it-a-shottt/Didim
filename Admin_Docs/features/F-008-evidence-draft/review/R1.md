## 지적
- [신규] [제안] [확실] 안 쓰는 코드와 어색한 중간 객체 — backend/app/services/draft_writing.py `DraftCheckResult.supported`(property)는 어디서도 안 부른다(draft_service.save_draft는 `sum(1 for item in sentences if item.supported)`로 따로 센다). 같은 파일 `_evidence_problem`은 `CheckedSentence(text="")`를 만들어 돌려주고, `check_ai_sentences`가 그 필드를 하나씩 새 `CheckedSentence`로 옮겨 적는다 — 확인한 범위: draft_writing.py 전체 + grep(`\.supported`) — 고치는 방법: `DraftCheckResult.supported`를 지우거나 save_draft가 그걸 쓰게 하고, 옮겨 적는 대신 `dataclasses.replace(checked, text=text)` 한 줄로 바꾼다.
- [제안] [확실] 다른 파일을 거친 가져오기 — backend/app/api/drafts.py가 `DraftNotFound`(원래 draft_view.py)와 `OtherAIWorkInProgress`(원래 note_claim.py)를 draft_service에서 가져가려고, draft_service.py에 `# noqa: F401` 재수출 두 곳을 뒀다. 쓰지 않는 이름이 import 목록에 남아 린터 경고를 가리고, 예외가 어디서 오는지 읽는 사람이 한 단계 더 찾아야 한다 — 확인한 범위: drafts.py · draft_service.py import 구간 — 고치는 방법: 라우터가 `draft_view.DraftNotFound`, `note_claim.OtherAIWorkInProgress`를 직접 가져오게 하고 draft_service의 noqa 두 줄을 지운다.
- [신규] [제안] [확실] 서식 · 오류 목록 두 곳 — ① drafts.py `_PREPARE_ERRORS`(튜플)와 `_prepare_error`(isinstance 사슬)가 같은 예외 7개를 따로 적는다. 예외를 하나 더하면 두 곳을 같이 고쳐야 하고 한쪽만 고치면 `raise exc`로 500이 난다 → 예외 → (상태, 문구) 딕셔너리 하나로 만들고 `except tuple(MAP)`로 쓰면 한 곳이다. ② 서식: draft_view.py `DraftNotFound`와 `matched_card_ids` 사이 · `matched_card_ids`와 `EvidenceView` 사이 빈 줄이 3줄(E303), drafts.py `INVALID_OUTPUT_DETAIL`과 `def get_draft_llm_client` 사이 빈 줄 1줄(E302), draft_service.py `save_draft`의 `if isinstance(exc, (ClaimLost, QuestionNotFound)) and get_application_for_user(...)` 한 줄이 140자쯤 — 확인한 범위: diff의 해당 구간 — 고치는 방법: `ruff format`(또는 `--select E`) 한 번.
