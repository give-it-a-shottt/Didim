## 지적
- [제안] [확실] ensure_db_ready 안에서 `from app.db.migrations import ensure_db_migrated`를 함수 안에서 import함 — 위치: backend/app/db/session.py:62 — 확인한 범위: migrations.py의 import 목록(alembic, sqlalchemy만, session을 import하지 않음) — 순환 import가 없어 지연 import 이유가 없고, 이유 주석도 없어 읽는 사람이 순환을 의심하게 됨. 파일 맨 위로 옮기거나, 이유가 있으면 한 줄 주석을 단다.
- [제안] [확실] 같은 이름 `migrations`가 두 곳에 있음(backend/migrations/ 폴더 = Alembic 환경, backend/app/db/migrations.py = 서버의 버전 확인). alembic.ini가 `prepend_sys_path = %(here)s`라 `import migrations`와 `app.db.migrations`가 서로 헷갈리기 쉬움 — 위치: backend/app/db/migrations.py (파일 이름), backend/alembic.ini:10 — 확인한 범위: 패킷의 두 경로와 alembic.ini — 파일 이름을 `schema_version.py` 같은 역할 이름으로 바꾸면 구분됨(바꾸면 session.py:62, tests/test_migrations.py:21의 import도 함께).
- [제안] [확실] 서버 시작 테스트 도우미가 모듈 내부 변수(_engine, _session_factory)를 직접 바꿔 끼우고, 가짜 값 `object()`를 넣어 "이미 만들어진 것"처럼 보이게 함. 반환 타입 표기도 없음 — 위치: backend/tests/test_migrations.py:99-107 — 확인한 범위: 이 fixture와 session.py:43-53 — session.py 내부 구조가 바뀌면 조용히 깨지는 결합. ensure_db_ready가 엔진을 인자로 받을 수 있게 하거나(`ensure_db_migrated(engine)`을 직접 테스트하는 현재 테스트가 이미 있어 우선순위는 낮음), 최소한 fixture에 `-> Callable[[Engine], None]`을 붙이고 이 결합이 의도라는 주석을 단다.
