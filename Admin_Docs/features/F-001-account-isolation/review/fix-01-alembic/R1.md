## 지적
- [제안] [확실] 1차 지적 3의 남은 부분: test_server_refuses_to_start_without_database_url이 여전히 session.py의 비공개 변수 `_engine` · `_session_factory`를 직접 비움 — 위치: backend/tests/test_migrations.py:194-195 (대응 변수 backend/app/db/session.py:44-45) — 확인한 범위: 이 테스트와 session.py:44-60 — session.py 내부 변수 이름이 바뀌면 이 테스트만 조용히 틀어짐(monkeypatch.setattr는 이름이 없으면 오류를 내므로 "조용히"는 아니고 바로 실패해 발견은 쉬움). 지금은 주석(192~193줄)이 의도를 설명하고 있어 우선순위 낮음. 고치는 방법: session.py에 테스트용 초기화 함수(`reset_for_tests()` 등)를 두거나 지금 그대로 두고 "내부 변수에 의존함"을 주석에 한 줄 더한다.
- [신규] [제안] [확실] `ensure_db_migrated`의 리스트 컴프리헨션 조건에서 `known_revisions()`를 revision마다 다시 부름. 부를 때마다 alembic 버전 파일을 다시 읽음 — 위치: backend/app/db/schema_version.py:90 — 확인한 범위: 패킷의 schema_version.py 전문과 실제 파일 62·90줄. 서버 시작 때 한 번이고 버전도 몇 개뿐이라 성능 문제는 없으나, 읽는 사람이 반복 호출로 오해하기 쉬움. 고치는 방법: `known = known_revisions()`를 컴프리헨션 앞에 한 줄 두고 `revision not in known`으로 쓴다.
