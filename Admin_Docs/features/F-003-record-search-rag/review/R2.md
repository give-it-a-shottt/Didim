## 지적

(2차는 지적 없음이었으므로 이번 지적은 모두 [신규]다. 보안 [위험]은 없다 — 원문 속 HTML · javascript:/data: 링크는 react-markdown 기본 동작으로 막힌다(아래 근거).)

1. [신규] [주의] [확실] 노트 상세의 마크다운 렌더링이 서버(Next.js)에서 동기로 돌아, 큰 원문이나 특이한 원문 하나가 서버 전체를 수 초~수십 초 멈춘다. 깊은 인용(`>` 반복)은 스택 넘침으로 화면이 오류가 난다.
   - 위치: frontend/src/components/note-markdown.tsx:327-333 (`<Markdown remarkPlugins={[remarkGfm]} …>`), frontend/src/app/(app)/records/[noteId]/page.tsx:89 (서버 컴포넌트에서 호출, 요청마다 렌더링)
   - 확인한 범위: react-markdown 10.1.0의 `Markdown`은 `processor.runSync`로 파싱 → 변환을 한 번에 동기로 한다(node_modules/react-markdown/lib/index.js `post` · `createProcessor`). 레포의 node_modules(react-markdown 10.1.0 · remark-gfm 4.0.1 · micromark 4.0.3)로 scratchpad 스크립트(r2js/md_time.mjs · md_time2.mjs · md_patho.mjs)를 만들어 Node 22 `renderToString`으로 이 PC에서 쟀다(컴포넌트 · rehype 플러그인 없이 같은 remark 설정, 실제 서버 수치는 다를 수 있음).
     - 서버 가드(파일당 1MB)를 통과하는 평범한 1MB 노트: 제목+문단+짧은 목록 반복 약 11초(remark-gfm 빼도 10.6초 → gfm 탓 아님), 표 반복 6.3~6.7초, 굵게 · 코드 · 링크 섞인 문단 1.5~1.8초, 코드 블록 1.1초, 여러 종류 섞음 13.2초.
     - 특이한 입력(키워드가 아니라 원문 모양만으로): `*a` 반복 10KB 0.29초 → 50KB 7.2초(제곱으로 늘어남, 1MB는 60초 넘어 중단), `_a*` 반복 50KB 13초, `[a](` 반복 50KB 0.7초 · 1MB 60초 넘음, `>` 반복 10KB부터 `RangeError: Maximum call stack size exceeded`(50KB는 7초 돈 뒤 오류).
     - Node는 한 줄(이벤트 루프)로 돌아, 렌더링하는 동안 같은 Next 서버의 다른 사용자 요청(로그인 · 검색 화면 등)이 모두 기다린다. 로그인한 사용자 누구나 이런 파일(.md, 1MB 이하)을 올려 그 노트를 여러 번 열면 서버를 계속 멈출 수 있다. 이전 회차(원문을 글자 그대로 출력)에는 없던 비용이다.
     - 원문을 고친 사람만 보는 화면이라 데이터 노출은 없다(보안 [위험]으로 보지 않음). 배포 전에는 정해야 한다.
   - 고치는 방법(사용자가 고를 선택이라 Q-00X 후보, 대안을 같이 둔다):
     - ① 크기 · 모양 상한: 원문이 N KB(예: 100KB, 측정해서 정함)를 넘거나 `>`·목록 들여쓰기가 일정 깊이를 넘으면 예전처럼 글자 그대로(`whitespace-pre-wrap` + 강조 구간) 보여 준다. 가장 작게 고칠 수 있다. 단, 50KB 특이 입력이 7~13초라 크기만으로는 모자라고 모양 검사를 같이 둬야 한다.
     - ② 클라이언트에서 렌더링("use client"): 비용이 그 노트를 연 사람의 브라우저에만 걸려 서버 전체가 멈추지 않는다. 회원 화면(noindex)이라 SEO 손해는 없고, 대신 번들에 react-markdown · micromark · remark-gfm이 더해진다(D-012 · 설계 원칙 8 "use client는 필요한 곳만"의 예외로 기록 필요).
     - ③ 가져올 때 한 번 변환해 저장(백엔드, 시간 상한을 둔 작업): 요청마다 파싱하지 않는다. 구조 변경이 커서 2차 범위에 가깝다.
     - 어느 쪽이든 `>` 깊은 인용 같은 입력으로 테스트를 하나 두면 다시 생기지 않는다.

2. [신규] [제안] [확실] 발췌용 링크 정규식 `_MD_LINK`가 닫히지 않은 `[`·`[](`가 한 줄에 많으면 제곱 시간으로 되돌아 찾는다. 지금은 조각 길이 상한 덕에 문제가 되지 않는다.
   - 위치: backend/app/search/query.py:21 (`!?\[([^\]\n]*)\]\([^)\n]*\)`), 호출은 query.py:72 → services/search_service.py:44 (검색 결과 조각마다, 최대 5개)
   - 확인한 범위: 레포 venv로 scratchpad 스크립트(r2_regex_time.py)를 돌려 쟀다. `strip_markdown` 입력 1,500자(= CHUNK_MAX_CHARS, chunking.py가 긴 줄도 이 길이에서 자름)일 때 `[` 반복 7ms · `![` 반복 7.5ms → 검색 한 번에 최대 약 40ms라 지금은 괜찮다. 같은 입력 2만 자 1.3초, 10만 자 32~34초(1MB 노트 전체에 쓰면 사실상 멈춤). 다른 정규식(코드 울타리 · 제목 · 목록 · 인용 · 인라인)은 10만 자에서 6ms 이하로 선형이다. 지금 호출하는 곳은 search_service 한 곳뿐이다(grep).
   - 고치는 방법: 글자 칸에서 `[`를, 주소 칸에서 `(`를 빼면 선형이 된다 — `!?\[([^\[\]\n]*)\]\([^()\n]*\)`(10만 자 1.5~3ms로 확인, 테스트 예문 `[2e92915 Redis 연결](https://…)` 결과 같음. 괄호가 든 주소 `[e](f(g))`는 지금 정규식도 `e)`로 어긋나므로 잃는 것은 거의 없음). 또는 함수 설명에 "조각(1,500자 이하)에만 쓴다"를 적어 노트 전체에 다시 쓰지 않게 한다.

3. [신규] [제안] [확실] 원문 속 이미지 `![](주소)`를 그대로 `<img>`로 그려, 노트를 열 때마다 브라우저가 그 주소로 요청을 보낸다.
   - 위치: frontend/src/components/note-markdown.tsx:300-323 (`img` 컴포넌트 지정 없음 → 기본 `<img src>`)
   - 확인한 범위: react-markdown `defaultUrlTransform`(node_modules/react-markdown/lib/index.js:421-443)은 http · https · mailto 등과 상대 주소를 그대로 둔다. 그래서 `![](https://외부/pixel)`은 노트를 열 때 외부 서버에 열람 시각 · IP가 남고(추적 픽셀), `![](/api/…)` 같은 상대 주소는 우리 도메인에 쿠키가 붙은 GET을 보낸다. 지금 프론트의 상태를 바꾸는 요청은 POST(logout-button.tsx:17)라 실제 피해 경로는 찾지 못했다. 원문은 내 기록이지만 남이 만든 .md를 받아 올릴 수도 있다. 노션 내보내기 이미지는 상대 경로라 어차피 깨진 이미지로 보인다. `data:` · `javascript:` 주소는 빈 값으로 바뀐다(위 함수로 확인).
   - 고치는 방법: `components.img`를 지정해 이미지를 그리지 않고 "[이미지: 대체 글]" 글자(또는 주소 링크)로 보여 주거나, 그릴 거라면 https만 허용 + `referrerPolicy="no-referrer"` · `loading="lazy"`. 이미지를 보여 줄지는 사용자 결정이라 Q-00X 후보.

## 체크 항목별 근거

보안 · 프론트
- XSS → react-markdown 10.1.0은 remark-rehype를 `allowDangerousHtml: true`로 돌리지만 rehype-raw가 없어 원문 HTML은 `raw` 노드로 남고, `post`에서 `{type: 'text'}`로 바뀐다(lib/index.js 360-366) → `<script>` · `<img onerror>`가 글자로 나온다. 링크 · 이미지 주소는 rehype 플러그인 뒤 `post` 단계의 `defaultUrlTransform`이 걸러 `javascript:` · `data:` · `vbscript:`는 빈 문자열(:421-443, 프로토콜은 `https?|ircs?|mailto|xmpp`만). scratchpad r2js/xss.mjs로 같은 설정(remark-gfm)을 렌더링해 확인: `<script>` · `<img onerror>` → 이스케이프된 글자, `javascript:` · `JaVaScRiPt:` · `data:text/html` · 참조 정의 `[f]: javascript:` · 자동 링크 `<javascript:…>` → `href=""`, `data:` 이미지 → src 없음, https는 그대로. `dangerouslySetInnerHTML` · `skipHtml` · `urlTransform` 덮어쓰기 · rehype-raw 없음(note-markdown.tsx 전체) → 문제 없음.
