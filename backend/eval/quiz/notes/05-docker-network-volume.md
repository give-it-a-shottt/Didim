# Docker 네트워크와 볼륨

## 기본 bridge 네트워크
`docker run`으로 그냥 띄운 컨테이너는 기본 bridge 네트워크에 붙는다. 기본 bridge에서는 컨테이너끼리 IP로는 통신할 수 있지만 컨테이너 이름으로 서로를 찾을 수 없다. 이름으로 찾으려면 사용자 정의 네트워크를 만들어 붙여야 한다.

## Compose의 서비스 이름 DNS
docker compose는 프로젝트마다 네트워크를 하나 만들고 모든 서비스를 거기에 붙인다. 그래서 백엔드 컨테이너에서 DB 주소를 `localhost`가 아니라 서비스 이름인 `db:5432`로 적는다. 컨테이너 안에서 localhost는 그 컨테이너 자기 자신을 가리키기 때문이다.

## 포트 공개
`ports: "127.0.0.1:5432:5432"`처럼 앞에 주소를 붙이면 호스트의 그 주소에서만 접속을 받는다. 주소 없이 `"5432:5432"`로 쓰면 모든 네트워크 인터페이스(0.0.0.0)에 열려서 같은 네트워크의 다른 컴퓨터도 DB에 접속을 시도할 수 있다.

## 볼륨과 데이터 보존
컨테이너를 지우면 컨테이너 안에 쓴 파일도 같이 사라진다. DB 데이터를 남기려면 이름 있는 볼륨을 `/var/lib/postgresql/data`에 연결한다. `docker compose down`은 볼륨을 남기지만 `docker compose down -v`는 볼륨까지 지우므로 데이터가 날아간다.

## depends_on의 한계
`depends_on`은 컨테이너를 시작하는 순서만 정할 뿐, DB가 접속을 받을 준비가 됐는지는 기다리지 않는다. 준비될 때까지 기다리게 하려면 DB 서비스에 healthcheck를 정의하고 `condition: service_healthy`를 함께 적는다.
