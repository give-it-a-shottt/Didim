# React 렌더링과 훅

## 다시 그려지는 조건
컴포넌트는 자기 상태(state)가 바뀌거나, 부모가 다시 그려지거나, 구독하는 Context 값이 바뀌면 다시 그려진다. props가 바뀌지 않아도 부모가 다시 그려지면 자식도 기본적으로 다시 그려지고, 이것을 막으려면 `React.memo`로 감싼다.

## useEffect 의존성 배열
`useEffect`는 화면이 그려진 뒤에 실행된다. 두 번째 인자인 의존성 배열을 빈 배열로 주면 처음 마운트될 때 한 번만 실행되고, 배열에 값을 넣으면 그 값이 바뀔 때마다 다시 실행된다. 배열 자체를 빼면 그릴 때마다 실행된다.

## 정리 함수
`useEffect`에서 함수를 반환하면 그것이 정리(cleanup) 함수다. 다음 effect가 실행되기 직전과 컴포넌트가 사라질 때 호출된다. 이벤트 구독이나 타이머를 effect에서 시작했다면 정리 함수에서 반드시 해제해야 메모리 누수와 중복 실행을 막을 수 있다.

## StrictMode의 두 번 실행
개발 모드에서 StrictMode로 감싸면 React는 effect를 일부러 마운트 → 정리 → 다시 마운트 순서로 두 번 실행한다. 정리 함수를 빠뜨린 버그를 일찍 드러내려는 장치이고, 프로덕션 빌드에서는 한 번만 실행된다.

## key의 역할
목록을 그릴 때 `key`는 React가 이전 항목과 새 항목을 짝짓는 기준이다. 배열 인덱스를 key로 쓰면 중간에 항목을 넣거나 지울 때 엉뚱한 항목의 상태가 남을 수 있다. 그래서 데이터베이스 ID처럼 항목마다 바뀌지 않는 값을 key로 쓴다.
